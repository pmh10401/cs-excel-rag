# 자료 준비와 질문 동시 실행 계획

> **For agentic workers:** Use superpowers:executing-plans. 승인된 제품화 2단계를 현재 세션에서 구현하고 마지막에 독립 검토한다.

**Goal:** 자료 준비 중에도 기존에 등록된 원문에 질문하고, 답변의 인용 근거를 조회 시점대로 유지한다.

**Architecture:** 준비 작업과 사용자별 질문 상태를 분리한다. 모델 호출을 짧은 읽기 트랜잭션 밖으로 이동하고 검색 결과의 원문 사본으로 재정렬·답변·검사를 끝낸다. 모델 요청 경계에서 질문 우선권과 준비 작업의 실행 기회를 보장한다.

**Tech Stack:** 기존 Python, SQLite, OpenAI 호환 API, 브라우저 JavaScript. 신규 의존성 없음.

**Spec:** `docs/제품화-설계-20261013.md`의 2단계.

## 공통 조건

- Windows 사내 서버 한 프로세스, 여러 브라우저. 실제 원문·검토·설정 보존.
- 원문과 키워드·영어·벡터 해시를 같은 읽기 트랜잭션에서 확인한다. 모델 대기 중 DB 읽기 트랜잭션을 유지하지 않는다.
- 기존 쓰기 작업 잠금·재시작 기록·CSRF·개별 질문 로그 격리 유지.
- 원문 DB의 저널 방식을 강제로 변경하지 않는다. 기존 rollback/WAL 모두 짧은 읽기 스냅샷을 지원하며, 긴 쓰기 구간의 대기는 별도 성능 개선 대상으로 명시한다.
- 로그인/권한 체계, PostgreSQL, 다중 서버, 모델 교체는 범위 밖이다.

## 검토 초점

1. 답변 대기 중 DB가 갱신되어도 인용에는 이전 원문이 남는가.
2. 같은 CS의 상세·영어·FAISS가 서로 다른 읽기 버전으로 섞이지 않는가.
3. 병렬 모델 작업의 진행률·소유자·재시작 기록이 질문과 섞이지 않는가.
4. 질문 우선권이 준비 작업을 영구히 굶기거나 Clef와 모델을 겹쳐 실행시키지 않는가.
5. 두 작업의 동시 표시·질문 완료·야간 중지가 브라우저에서 유지되는가.

## 검토 보완 기록

독립 검토에서 동시 질문 이후 일괄 채택·벡터·영어 처리의 실패 상세가 화면에서 빠지는 문제를 확인했습니다. `refreshJob`의 종료 처리를 공통 함수로 옮겨 질문과 준비 결과 각각에 적용합니다. Node 표준 라이브러리로 실제 완료 처리 함수를 실행하는 검사를 추가했고, 실패를 재현한 뒤 통과했습니다. 자료 복구 안내가 생겨도 내 질문 답변을 표시하고 같은 결과를 반복 처리하지 않는 경우도 포함합니다. Node가 없는 Windows에서는 이 선택 화면 검사만 생략한다고 표시합니다.

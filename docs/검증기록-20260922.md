## 야간 무제한 재시도와 화면 개선

실행된 야간 작업은 자료 읽기·다듬기·자동 채택·벡터·영어·최종 검색 색인의 실패를 재시도합니다. 실행 전 입력·설정 검증은 유지합니다. `tests/test_overnight.py`에서 실제 SQLite와 모의 모델로 다음을 확인했습니다.

- 다듬기·번역 실패 뒤 성공 복구, 인증 오류 두 번 후 복구, HTTP 401 실패 목록의 재시도 대기와 중지.
- 자료 읽기·자동 채택·벡터·영어·최종 색인 예외를 각각 주입한 뒤 복구. 시도 횟수는 2·1·2·2·2·2회이며 완료한 단계는 반복하지 않았습니다.
- 자동 채택 검사 실패 접수만 오류 사유와 함께 다시 다듬기. 손상된 이전 제안도 검사 오류를 전달해 다시 생성하고 정상 접수는 재사용했습니다.
- 상태 보고 파일의 PermissionError가 DB 처리·준비 완료를 막지 않으며 화면 상태에 경고를 남기는지 확인했습니다.
- 중지 시 진행 중 요청의 성공분을 저장하고 후속 요청을 차단하며, 중지를 검색 준비 완료로 표시하지 않았습니다.

```sh

.venv/bin/python -c 'from pathlib import Path; from tests.test_review_workflow_ui import main; main(Path.cwd())'
node --check ragkit/assets/app.js
```

전용 브라우저 도구 대신 설치된 Playwright를 사용했습니다. 시험용 서버의 실제 HTML/CSS/JS와 8건 DB, 모의 모델 응답으로 1440×1000 및 390×844 화면을 검사했습니다. 제목·본문·초기 화면, 파일 입력 접기와 대기열 접근, 두 번째 자동 실패 회차, 실행 중 새로고침, 중지와 재개, 6단계 완료, 질문 화면 이동, 개별 실행 영역을 확인했습니다. 임베딩 미설정은 건너뜀·키워드 준비로 구분했고, 가로 넘침·열린 대화상자 가림·콘솔 오류가 없었습니다. 화면 로직 검사에서는 오류 문구를 HTML로 실행하지 않는 점과 중지 요청 버튼 잠금, 다른 자료 작업 뒤 이전 완료 표시 제거도 확인했습니다.

검사는 재시도 대기 시간을 줄여 실행했습니다. 실제 야간 장시간 실행이나 Windows 실기기·운영 GPT OSS 120B의 품질·성공률 검증은 아닙니다. 프로그램 재시작 후 자동 재개는 제공하지 않으며 사용자가 버튼을 다시 누르면 DB 성공분을 재사용합니다. 사용 설명, 전체 흐름도, 임원 보고서와 Word 4쪽을 함께 갱신하고 모든 페이지를 렌더링해 확인했습니다.

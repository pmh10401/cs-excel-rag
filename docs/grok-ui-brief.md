# CS RAG 로컬 웹 UI — Grok 구현 지시서

구현은 Grok 4.6 / xhigh가 맡고, Codex는 통합·회귀검사·브라우저 검증을 맡는다.
이 프로젝트의 Grok 호출에는 `--model grok-4.6 --reasoning-effort xhigh`를 명시한다. 설치된 CLI의 최고 추론 단계는 `xhigh`이며 `max`는 지원하지 않는다.
대상은 Windows와 Mac에서 혼자 사용하는 기존 Excel RAG이다. 설치된 Python과 기존 라이브러리를 재사용한다.

## 첫 버전의 범위

기존의 입력 선택 → 문장 다듬기 → 셀 검토 저장 → 질문·근거 조회를 한 로컬 웹 UI에서 수행한다.
시트는 CSList 하나이며, 열 규칙과 원문·제안·채택문의 구분은 기존 코드를 따른다.
새 임베딩, 학습, DB 이전, 로그인, 클라우드 배포, npm 프로젝트는 추가하지 않는다.

### 화면

- 사이드바: 자료 / 문장 검토 / 질문. 설정은 작은 패널로 제공한다.
- 자료: Excel 전체 경로, 일반 파일 또는 Windows Excel에서 열린 파일 읽기, 입력 검사 결과, 현재 자료 건수, 문장 다듬기 실행.
- 문장 검토: 접수 목록·검색·페이지 이동, 선택한 접수의 작업별 원문과 수정문 비교. 채택·원문 유지·직접 편집 후 명시적인 저장 버튼으로 DB에 반영한다. 미저장 변경을 표시한다.
- 질문: 질문 입력, 실제 처리 상태와 경과 시간, 답변, 인용한 접수·작업·열·원문 셀 위치. 근거를 누르면 해당 원문을 확인한다. 없는 기록과 검사 실패는 성공 답변과 구분한다.
- 설정: 실제 사용 중인 모델·서버·추론 옵션을 표시한다. 첫 버전에서 설정 파일을 편집하는 별도 폼까지 만들 필요는 없다. API 키를 응답·HTML·로그에 노출하지 않는다.

Apple 스타일의 밝은 회색 배경, 흰색 패널, 시스템 글꼴, 충분한 여백, 얇은 구분선, 절제된 파란 강조색을 사용한다. 장식용 통계·가짜 대화·마케팅 문구를 넣지 않는다. 한국어 버튼과 설명을 사용하고, 현재 상태와 다음 행동을 명확히 보여 준다. 좁은 화면에서도 탐색과 입력이 가능해야 한다.

## 구현 경계

새 서버는 Python 표준 라이브러리의 HTTP 서버와 스레드로 충분하다. 정적 HTML/CSS/JavaScript를 사용한다.
권장 파일은 `ragkit/web.py`, `ragkit/assets/app.html`, `app.css`, `app.js`이며, 기존 실행 파일에 `--ui` 진입점만 추가한다. 기존 콘솔 실행은 유지한다.
공통 로직을 복제하거나 완화하지 않는다. 다음 함수를 읽고 재사용한다.

- `records.read_excel`: 입력 검사, CSList와 128열, 자료형·빈칸·위치 보존.
- `cslist.load_schema`: 양식과 수정 규칙.
- `storage.ingest`, `prepared_record`, `apply_reviews`: 제안 생성·조회·검토 적용.
- `search.retrieve`, `count_records`: 검색과 전체 DB 집계.
- `llm.answer`, `validate_claims`: 근거 검사와 보정. 이 파일은 수정하지 않는다.
- `cli.py`, `menu.py`: 현재 설정·결과 폴더·원문 변경 확인 규칙을 참고한다.

실행 인자로 root/config/output을 받아 Mac과 압축 해제된 Windows 배포 구조에서 모두 동작하게 한다. 새 UI 기본 출력은 기존 자료를 조용히 덮어쓰지 않는 별도 폴더로 정하고, 사용자가 선택한 파일과 검토 결과를 다시 열 수 있게 저장한다. 화면에는 실제 출력 위치를 표시한다.
목록은 페이지 단위로 응답한다. 2,000건의 128열 전체를 초기 화면에 렌더링하지 않는다.
`ingest(client=None)`는 기존 제안을 지우므로 이미 다듬은 DB를 단순 조회·입력 검사 과정에서 이 함수로 갱신하지 않는다.
질문 전에는 선택한 Excel이 저장된 원문과 같은지 확인한다. 변경됐으면 기존 자료로 조용히 답하지 않고 갱신을 안내한다.

### 실행과 오류

- 긴 모델 작업은 백그라운드 작업 하나로 실행하고 화면에서 상태를 조회한다. 중복 실행을 막고 DB 연결은 작업 스레드 안에서 만든다.
- Windows의 xlwings 읽기는 작업 스레드에서 COM 초기화·해제를 처리한다. 원본 통합문서를 열거나 저장·종료하지 않는다.
- 실제 진행 정보를 모르면 백분율을 만들지 말고 단계·진행 중·경과 시간으로 표시한다.
- 제안이 없는 상태, 자료가 없는 상태, 빈 질문, 읽기 실패, 원문 변경, 모델 연결 실패, 근거 검사 실패, 검토 저장 실패를 처리한다.
- 검토 변경은 사용자가 저장한 항목만 전달하고 기존 source_key·revision 검사를 유지한다. 자동 채택하지 않는다.
- 작업 실패를 정상 완료로 표시하지 않고 원문과 이미 저장된 검토 데이터를 보존한다.

### 로컬 서버 경계

- 127.0.0.1에만 바인딩하고 허용한 정적 파일과 API만 제공한다. 디렉터리 목록·임의 파일 제공은 금지한다.
- Host/Origin 검사와 실행 시 만든 세션 토큰으로 다른 웹사이트에서 로컬 변경 API를 호출하지 못하게 한다. CORS 와일드카드는 사용하지 않는다.
- JSON 요청 크기·타입·필수 값·목록 범위를 검사한다. 파일 경로나 질문을 셸 문자열로 실행하지 않는다.
- 입력·모델 문장은 textContent 또는 HTML 이스케이프로 표시한다. 오류 메시지에 비밀키·스택 전체를 노출하지 않는다.
- 키보드 조작, 명시적 label, 포커스 표시, 상태 알림과 대비를 갖춘다.

## Grok 작업 제한과 산출물

별도 worktree에 제공한 코드와 이 문서만 읽는다. 원본 저장소·공식 결과 폴더·DB·기존 평가 자료·인증 파일은 접근하지 않는다.
소스 파일 편집만 한다. 프로세스·서버·모델 요청 시작, 설치, 다운로드, commit/push, 다른 에이전트 호출은 하지 않는다.
기존 파일 수정은 진입점 연결에 필요한 최소 범위로 제한한다. `ragkit/llm.py`, `storage.py`, `search.py`, `records.py`, `excel_app.py`는 수정하지 않는다.
새 외부 의존성 없이 구현하고, 바뀐 파일·설계 선택·실행 방법·검증이 필요한 경계를 짧게 보고한다. 실행하지 않은 검사를 통과했다고 쓰지 않는다.

Codex는 실제 SQLite·임시 가상 Excel·모의 모델 응답으로 입력/검토/질문/오류 흐름을 검사하고, 로컬 브라우저에서 데스크톱·좁은 화면·키보드·근거 펼치기·오류 표시를 확인한다. 검증 중 운영 DB를 변경하거나 2,000건의 LLM 다듬기를 자동 실행하지 않는다.

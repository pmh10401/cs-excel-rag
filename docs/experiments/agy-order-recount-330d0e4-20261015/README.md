# 기존 검색 순서와 Clef 순서의 전후 비교

2026-10-15 KST · **저장 결과의 사후 재집계**

입력은 고정 커밋 `330d0e4d1d4ffb08bd958eef9f115b472933c751`의 `docs/experiments/agy-breadth-20261014-r3/`만 사용했다. 해당 커밋의 생성 코드는 출처 확인을 위해 읽기만 했다. 신규 추론·검색·임베딩·평가 데이터 생성·정답 수정은0회다. 운영 DB·설정과 원래 결과를 변경하지 않았다.

## 적용 전 순서의 확인

- [검색 결과 저장 코드](https://github.com/pmh10401/cs-excel-rag/blob/330d0e4d1d4ffb08bd958eef9f115b472933c751/experiments/agy_breadth.py#L142-L149)는 `semantic.search_cases(... mode="hybrid", limit=20)`의 반환 hits를 그대로 고정한다.
- [검색 함수](https://github.com/pmh10401/cs-excel-rag/blob/330d0e4d1d4ffb08bd958eef9f115b472933c751/ragkit/semantic.py#L385-L406)는 RRF 결합·중복 처리·기존 조치 다양성 처리를 거쳐 selected를 반환한다. 기준은 **hybrid로 설정한 기존 검색 함수의 최종 반환 순서**다. BM25 단독·벡터 단독을 별도 실행한 대조군이 아니다.
- [공개 내보내기](https://github.com/pmh10401/cs-excel-rag/blob/330d0e4d1d4ffb08bd958eef9f115b472933c751/experiments/agy_publish.py#L33-L38)는 저장 hits를 순회해 ids를 만들고 정렬하지 않는다. Clef는 같은 hits의 앞5건을 받아 재정렬한다.
- 고정 manifest25파일과 검색·실행기·Clef 소스의 고정 프로토콜 해시를 대조했다. 저장 input/execution 감사는 입력 지문 일치와 후보 불변을 기록한다. 이 코드·기록에 근거해 ids를 해당 실험의 Clef 적용 전 검색 순서로 확인했다.
- 검색 함수에는 정확 조회·벡터 실패의 별도 반환 경로도 있다. 공개 후보 파일에는 질문별 검색 details가 없어 모든 문항에 RRF가 실제 적용됐는지는 독립 확인하지 않았다. 함수의 반환 순서를 기준으로 비교하며 이를 순수 RRF 순서라고 확대하지 않는다.
- 고정 커밋에는 원래 candidates.jsonl·candidate-freeze.json·GPU 원시 요청은 들어 있지 않다. 원시 검색 실행을 독립 재현하거나 공개 내보내기를 원시 파일과 새로 바이트 대조한 것은 아니다. 저장 감사 기록을 새로운 독립 검증으로 표현하지 않는다.

## 후보5건 전후 비교표

첫 기대ID는 첫 후보가 고정 실버 기대ID 중 하나인 문항 수다. 상위3은 기대ID가 하나 이상 포함된 문항 수다. 각 개선/악화/동일은 그 지표의 이진값 변화이며 순서 전체의 동일을 뜻하지 않는다. 후보 누락도 주 분모에 포함했다.

|구분|문항|첫 기대ID 전→후|상위3 전→후|첫 개선/악화/동일|상위3 개선/악화/동일|후보5 누락|
|---|---:|---:|---:|---:|---:|---:|
|주 비교 합계|120|72→113|113→113|41/0/79|0/0/120|7|
|운전 조건|20|13→20|20→20|7/0/13|0/0/20|0|
|상세·작업|20|4→18|18→18|14/0/6|0/0/20|2|
|다국어·표현|20|5→15|15→15|10/0/10|0/0/20|5|
|숫자·단위|20|20→20|20→20|0/0/20|0/0/20|0|
|조치 상태|20|16→20|20→20|4/0/16|0/0/20|0|
|현상·조치|20|14→20|20→20|6/0/14|0/0/20|0|
|별도 정확 조회·우회|20|—|—|—|—|대상 아님|
|별도 집계·우회|20|—|—|—|—|대상 아님|
|별도 후속 질문·우회|20|—|—|—|—|대상 아님|
|별도 기대ID 없음·실제 재정렬|20|—|—|—|—|대상 아님|

주 비교120문항은6유형×20이며 모두 실제 재정렬 status=ok다. 후보 집합/개수 불일치는0/120, fallback·우회는0/120이다. 신규 TEST 전체200문항도 후보 다중집합200/200 일치를 확인했고 CSV에 모두 남겼다. 정확 조회·집계·후속은 각각20문항 우회이며, 근거 없음20문항은 실제 재정렬됐지만 기대ID가 없어 주 순위 분모에서 분리했다. DEV40·회귀24는 이번 주 분석에서 제외했다.

첫 기대ID는 72/120(60.00%) → 113/120(94.17%), 관찰 차이+34.17%p다. 상위3은113/120(94.17%)으로 전후 동일하다. 기대ID가 후보에 있는113문항 중 기존 첫 기대ID72건이 Clef 후113건이지만, 이 조건부113분모로 전체120분모를 대체하지 않는다.

후보5 누락7건은 상세2·언어5다. 그중 5건은 저장 전체 후보20건 안에는 있으나 앞5건 밖에 있고, 2건은 전체 저장 후보20건에도 없다. 재정렬은 후보에 없는 기대ID를 추가할 수 없다. Clef 후 후보 내 기대ID를 첫 자리에 두지 못한 실패는0건이고, 남은 첫 선택 실패7건은 모두 후보 누락이다.

첫 지표 동일79건은 기대ID 첫 선택 유지72·기대ID 누락 유지7건이다. 실제 후보 순서 전체가 동일한 수는30/120, 첫 후보ID가 그대로인 수는79/120이며 별도 개념이다.

## 생성군과 한계

120문항은20개 생성군에서 각6유형이 파생된 합성/실버 자료다. 질문별 CSV에 group_id를 유지하고 그룹별 집계20행도 제공한다. 독립 현장 표본120개나 담당자 평가로 세지 않는다. 이번 사후 표의 문항 비율을 모집단 정답률·통계적 일반화·새 독립 검증으로 해석하지 않는다. 라벨의 의미 타당성을 재판정하지 않았으며 모호한 상태 표현·직접적 설비명이 있는 합성 질문이라는 기존 한계도 그대로다.

## 발표에서 사용할 수 있는 결론

> 고정한 합성 평가의 실제 재정렬 대상120문항에서, 같은 후보5건의 순서만 비교한 사후 재집계 결과 첫 기대 근거 선택은72건에서113건으로 늘었다. 개선41건·악화0건·지표 동일79건이었다. 상위3 포함은113건으로 같았고, 기대 근거가 후보에 없는7건은 해결되지 않았다.

이는 기존 혼합 검색 대비 저장 순위 변화다. 후보 수 확대 비교나 최종 답변 정확도 비교가 아니다. 기존에도 기대 근거가 상위3 안에 있었으므로 답변 모델이 받는 최대3건의 품질/최종 답변 향상을 이 수치만으로 주장하지 않는다. 범용 재정렬 모델과의 새 대조·현장 효과·Windows 성능·Clef 고유 우위는 확인하지 않았다.

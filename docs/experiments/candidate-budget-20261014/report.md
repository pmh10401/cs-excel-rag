공통 결합 검색 목록 20개를 고정한 뒤 앞 5·10·20개를 Clef로 재정렬했다. 답변은 미리 고른 새 질문 6개에 세 구성을 적용했고, 모두 근거 3개를 제공하도록 설정했다. 관계 보완·영어 번역은 끄고 기존 모델·지시문·검사·보정 한도를 유지했다.

재정렬 72회는 정상 실행했다. 답변은 18시도 중 13시도만 모델에 진입했고 4시도에서 답변을 제공했다. 후반 JSON 오류로 전체 최종 답변 비교는 불완전하며, 아래에 실패와 공통 실행 질문을 분리했다.

표의 시간은 요청별 모델 적재·추론·프로세스 정리를 포함한다. 순수 추론과 적재 중앙시간, 실제 입력 토큰 범위, RSS는 ranking-summary.csv에 따로 기록했다. MLX 피크는 추론 측정 범위이며 답변 모델이나 시스템 전체 메모리가 아니다.

Hit@K는 해당 입력 후보 안의 직접 적합 근거 포함 여부다. 후보 집합이 달라 K별로 달라질 수 있지만, 같은 K의 재정렬 전후에는 같아야 한다. 전체 관련 문서의 재현율이나 현장 정답률이 아니다. 후보 수가 다른 Clef 상대 선택 확률을 직접 비교하거나 정답 확률로 해석하지 않는다.

후반 LM Studio의 `lms ps --json` 파싱 오류로 일부 시도는 답변 모델에 도달하지 못했고, 모델에 도달한 시도 중 한 시도는 정리에 실패했다. 사전 실패 시도에서도 같은 정리 오류가 반복 기록됐다. 원시 stdout은 실행기가 보관하지 않아 파싱 오류의 원인은 확정하지 못했다. 종료 후 모델 목록은 정상 JSON으로 복구되었고 남은 실험 전용 idle 모델을 별도로 해제해 목록이 비었음을 확인했다. 원래 실패 기록을 수정하거나 같은 request key로 재실행하지 않았다.

따라서 18건은 성공한 답변이나 모두 정상 실행한 모델 흐름이 아니라 계획한 시도 수다. 전체 시도 중앙값에는 약 1초 만에 끝난 사전 오류가 포함되므로 K별 응답 속도 우위로 해석하면 안 된다. 모델 진입 시도만의 값도 질문 구성이 달라 공정한 전체 비교가 아니다.

실제 답변 흐름은 임베딩·검색·Clef 재호출·답변 모델 적재·생성·검사·최대 1회 보정/재요청·정리를 포함한다. 이전 순위의 재생 시간이나 성공 요청만의 평균이 아니다. actual_output_cap과 최초 순위/답변용 재호출의 상위 3개 차이는 answer-summary.csv에 보존했다.

자동 사실 진단은 기존의 명시적 문자열·수치·상태·원문 주소 검사에 한정된다. 의역은 unknown이며 모든 의미·상세 연결·현장 조치 적합성을 검증하지 않는다. 현재 검사기를 최종 정답 점수로 재사용하지 않았다.

두 번째 호출은 오류에 따른 보정 또는 재요청이며, 반드시 수정 프롬프트가 전달되었다는 뜻은 아니다. 출력 한도는 추론 토큰도 포함한다. length 종료와 실제 출력 상한을 기록하며, 잘린 응답을 성공이나 근거 부족 답변으로 바꾸지 않는다. 답변이 제공되지 않은 경우 후보 규모만으로 최종 의미 품질을 비교할 수 없다.

기존 합성 배경 2,000건과 이전 v3 조건 38건을 결합했다. 새 질문도 같은 규칙적 합성 배경에서 만들었고 이전 12질문은 회귀 진단이다. 기존 v3와 corpus가 달라 해당 5건 점수를 그대로 새 기준선으로 재사용하지 않았다. 생성군/같은 원본의 변형을 독립 표본으로 세지 않는다. 새 질문은 부품별 6개 군집, 각 2질문이며 결과는 기술 진단이다. 통계적 우위나 동등성을 확정하지 않는다.

## 범위와 남은 한계

Mac M2 Max 32GiB, Clef 8bit MLX GPU, 기존 EmbeddingGemma2, GPT-OSS 20B Metal/high 추론을 사용한다. 새 설치·다운로드·운영 DB/설정 변경·자동 채택은 없다. Windows/DRM·120B·10만 건·사람 업무 효과·범용 모델보다 우위는 미검증이다. 이 시험은 Clef의 후보 범위 비교이며 Qwen 등 다른 재정렬 모델의 후보 규모 효과를 함께 비교한 것은 아니다. 근거 없는 질문의 거절 능력도 이번에 추가 검증하지 않았다. 요청은 한 번에 하나씩 실행했으며 다중 사용자 부하·상주 모델 속도·시스템 전체 메모리는 측정하지 않았다. 자원 대기는 전체 wall에 포함하지만 독립적인 queue_wait 값으로 분리하지 않았다. Clef는 현재 원문 직렬화·지시문·응답 검사를 재사용하되 HTTP 전송을 격리 MLX GPU 자식 실행으로 연결했다. 임베딩·답변은 실제 로컬 LM Studio HTTP 호출이다. 브라우저 통신·웹 서버 대기열을 포함한 운영 사용자 지연으로 해석하지 않는다.

실제 답변 호출 24/상한 36. 독립 순위 시도 wall 합 2394.813초, 답변 18시도 wall 합 3474.701초다. 답변 흐름에 포함된 Clef 시간을 다시 더하지 않는다. 오프라인 임베딩 구축·질문 준비·후보 고정 비용은 cost-summary.json에 별도 기록한다. 인덱스 등록 건수와 중복 텍스트를 제외한 실제 생성 건수를 구분한다. 전체 모델 요청·실패·첫 응답·보정 응답은 로컬 원시 기록에 보존한다. RSS·MLX 메모리를 합산하지 않으며 답변 GPU 피크는 미측정이다.

## 판단과 발표 범위

이번 질문에서는 처음 5건에 이미 직접 적합 근거가 모두 있었다. 10·20건으로 늘려 누락 정답을 새로 찾은 효과는 관찰할 수 없었다. 후보가 더 필요한 질문 전반에서 확대가 불필요하다는 결론은 아니다.

후보 확대만으로 최종 답변 품질이 올라간다고 판단하지 않는다. 운영 기본값은 유지한다. 표본은 작고 같은 부품군의 변형을 포함하며 각 질문·구성은 한 번 실행했다. 이 비교만으로 통계적 우위나 동등성, 안정적인 대기 시간을 주장하지 않는다.

- 발표 가능: 고정한 합성 자료에서 후보 범위별 선택 결과·관찰한 악화·실제 GPU 호출 비용·답변 실패를 함께 측정했다.
- 발표 불가: Clef 고유 우위, 현장 정답률·업무 시간 절감, Windows/120B 성능, 후보 20건의 보편적 품질 개선, 모든 의미 오류의 차단.

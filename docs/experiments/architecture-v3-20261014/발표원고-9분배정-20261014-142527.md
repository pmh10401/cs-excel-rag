## 1. 55초 배정

이번 발표는 과거 CS에서 지금 질문의 조건에 맞는 원문 근거를 찾는 구조를 설명합니다. 상세와 작업, 원문 셀을 유지하고 검색과 선택, 답변과 검사를 나누었습니다. 평가 기준은 AI 적합성30, 확산성40, 효과20, 적용 독창성10입니다. 남은 시간 안에 사람이 참여하지 않는 합성 검증을 수행했으며, 업무시간 절감이나 실제 타팀 도입 성과는 측정하지 않았습니다.

## 2. 45초 배정

이 두 원문은 설명을 위해 창작한 합성 기록입니다. 첫 기록은 실제 유량이 낮으면서 환수 온도가 높고, 두 번째는 유량이 정상인데 환수 온도가 높습니다. 냉각수와 온도라는 단어는 비슷하지만 기록된 조치는 다릅니다. 질문의 필수 조건이 원문에 명시되어 있을 때만 직접 적합으로 분류했습니다. 조건이 없으면 불명으로 두고, 선택 점수가 높다는 이유로 성공한 조치라고 부르지 않았습니다.

## 3. 55초 배정

정확한 접수번호와 코드, 날짜, 지원하는 집계는 규칙 경로가 맡습니다. 표현이 다른 현상은 키워드와 벡터로 후보를 찾습니다. 선택 단계는 이미 찾은 후보의 순서를 바꾸며 빠진 근거를 새로 만들지는 못합니다. 답변 모델은 선택한 원문으로 설명하고, 프로그램은 상세와 셀, 수치와 인용을 대조합니다. 실패한 경우 제한된 보정이나 답변 보류가 있으며 원문은 유지합니다. 이 단계 분리는 다른 도구에서도 구현할 수 있는 설계입니다.

## 4. 65초 배정

새 조건 질문24개,12대조쌍을 고정했습니다. N은 원문 기반 비AI 검색, V는 벡터 진단, H는 결합 검색, G는 이미 준비된 범용 Qwen4B, HC는 같은 H후보에 Clef를 적용한 결과입니다. 첫 직접 적합은 H 17/24, HC 23/24입니다. 후보를 바꾸지 않으므로 H와 HC의 Hit@5는 같아야 합니다. 대조쌍 두 질문을 모두 맞췄는지도 표시했습니다. 이 작은 합성 결과를 현장 정확도나 Clef의 보편적 우위로 확대하지 않습니다.

## 5. 50초 배정

선택 순위가 바뀌어도 답변 모델이 여러 후보를 읽으면 차이가 작을 수 있습니다. 이를 확인하기 위해 순위 결과를 보기 전에 정한8질문에 H상위3개, Clef후3개, H상위5개를 각각 제공했습니다. 총24답변 흐름이며 보정 호출도 포함했습니다. 표의 사실충족은 원문 셀과 상세, 수치, 명시적 상태 및 필수 조치의 기계 확인 가능한 항목만 검사한 결과입니다. 인식하지 못한 의역은 unknown입니다. 전체 시간에는 검색과 모델 적재·교대, 생성·검사·보정·정리가 포함되며 최종 의미 정확도나 담당자의 업무 완료 시간이 아닙니다.

## 6. 60초 배정

정상 답변12개와 한 항목만 바꾼 오류12개에 같은 현재 검사를 적용했습니다. JSON 구조는 유효하게 유지해 파싱 오류만 세지 않았습니다. 상세와 셀, 수치와 날짜, 다른 작업의 조치를 가져오는 경우, 예정이나 미실시를 완료로 바꾸는 경우를 나눴습니다. 검사가 잡은 오류와 놓친 오류, 정상 오거절을 모두 표시합니다. 의도적으로 주입한 오류이며 모델이 실제로 낸 오류12건이 아닙니다. 의미 오류가 통과한 경우도 숨기지 않고 이 검사의 보호 범위로 한정합니다.

## 7. 65초 배정

누적28열과 CSList128열, 냉각·진공·반송의 여섯 합성 입력을 같은 공통 코드로 처리했습니다. 양식마다 행과 작업의 구조가 다르므로 ID문자열이나 행수 자체를 억지로 같게 만들지 않았습니다. 원문과 자료형, 상세와 작업20개를 작성기 쪽의 예상값과 저장된 값으로 대조했습니다. 정확 조회와 현상 검색 경로를 확인했고 임베딩 호출이 실제로 있었는지도 분리했습니다. 이는 이미 지원하는 양식의 재사용 기술 확인이며 임의 Excel지원이나 실제 타팀 도입 성과는 아닙니다.

## 4. 자료 등록부터 한국어 답변까지

흐름은 두 부분입니다. 먼저 자료 준비입니다. Excel을 읽어 원문과 셀 위치를 보존하고, 한 접수의 여러 상세를 구분합니다. LLM이 읽기 쉬운 문장을 제안하면 검사와 검토를 거칩니다. 영어 번역은 선택 사항입니다. 이후 키워드 색인과 뜻을 비교하는 임베딩을 준비합니다. 질문 단계에서는 한국어 문제 현상으로 관련 사례를 찾습니다. 선택적으로 Clef가 후보 순서를 보완하고, 답변 LLM은 찾은 원문으로 한국어 답변을 작성합니다. 마지막으로 숫자, 단위, 인용과 상세 범위를 검사합니다. LLM이나 Clef를 쓴다고 사실이 자동 검증되는 것은 아닙니다. 끝까지 사실의 기준을 원문에 두는 것이 핵심입니다.

## 5. 같은 CS의 다른 조치를 섞지 않는 구조

이 표는 구조를 설명하기 위한 가상 사례입니다. 같은 CS 번호 아래 상세 A에는 펌프 누수와 씰 교체 예정이 있습니다. 상세 B에는 밸브 응답 지연과 커넥터 재체결 후 동작 확인이 있습니다. 여기에서 펌프 질문에 밸브의 조치를 가져오면 안 됩니다. 또 교체 예정이라는 기록을 교체 완료로 바꾸면 안 됩니다. 이를 위해 접수번호 아래의 상세를 나누고, 답변에 사용한 조치가 어느 상세의 어느 셀에서 왔는지 확인합니다. 정리문이나 번역문이 바뀌어도 원문은 남습니다. 다만 숫자와 인용이 맞아도 문장의 모든 의미가 맞는 것은 아니므로, 계획과 완료 또는 미실시 같은 상태를 현장 검증에서도 별도로 보겠습니다.

## 6. 답변과 근거를 분리한 사용자 화면

실제 브라우저의 기능 확인 화면입니다. 이 화면은 가상 자료와 모의 모델로 확인한 것이므로 표시된 응답 시간을 모델 성능으로 해석하지 않습니다. 위에는 핵심 답변을 보여주고, 아래에 인용한 접수와 원문을 따로 둡니다. 사용자는 답변을 읽다가 근거가 필요할 때 실제 셀을 펼쳐볼 수 있습니다. 관계 보기에서는 검색된 상세와 설비, 부품의 연결을 확인하고, 이어서 질문할 수도 있습니다. 원문을 처음부터 길게 섞어 보여주는 대신 필요한 깊이로 확인하는 흐름입니다.

## 7. 합성 자료에서 확인한 검색 개선

검색 성능의 근거입니다. 10만 건은 합성 자료의 규모이며, 10만 개의 질문을 평가했다는 뜻은 아닙니다. 미리 정한 50문항 중 정답이 있는 44문항을 보겠습니다. 첫 번째 결과가 정답인 경우는 키워드만 사용할 때 28건, 기존 Qwen 결합 검색은 39건, 현재 EmbeddingGemma 2 결합 검색은 35건입니다. 현재 구성은 키워드 단독보다 7문항을 더 찾았습니다. 동시에 기존 모델이 이번 질문에서는 더 좋았다는 점도 확인했습니다. 따라서 최신 모델 교체 자체를 성과로 보지 않고, 업무 질문에 맞는 선택이 필요합니다. 이 결과는 반복 사용한 개발 질문의 검색 시험입니다. 답변 정확도나 경쟁사 대비 우위로 확대 해석하지 않습니다. 별첨에는 상위 다섯 개 포함 여부, 근거 없는 질문과 오류 사례도 함께 제시했습니다.

## 8. 자료 준비와 질문을 함께 처리하는 운영 구조

운영을 위해서는 답변 품질뿐 아니라 중단과 동시 사용에 대한 처리가 필요합니다. 여러 파일 등록과 야간 준비는 성공 상태를 저장하고, 서버를 다시 실행하면 남은 부분부터 이어갑니다. 관련 복구 검사 14건을 통과했습니다. 자료를 정리하는 동안에도 질문을 접수하고, 검색할 때 읽은 원문을 답변이 끝날 때까지 유지하는 동시 처리 검사 7건도 통과했습니다. 이 숫자는 Mac의 모의 모델 기능 검사 건수입니다. 동시 사용자 수나 처리 속도의 실측치가 아닙니다. 실제 Windows의 DRM 입력, 120B 모델 대기 시간, 사용자와 관리자 권한 분리는 현장 적용 전에 확인해야 합니다.

## 9. 경영 기여는 현장 시범 적용으로 측정

경영 기여는 기대효과와 측정 결과를 구분하겠습니다. 우선 한 설비군에서 개발에 쓰지 않은 질문 50건을 담당자가 판정하는 시범 적용을 제안합니다. 같은 과제에서 기존 Excel 검색과 서비스 사용 시간을 비교하고, 상위 다섯 개 안에 정답이 있는지와 잘못된 조치를 안내했는지를 함께 보겠습니다. 원인이나 결과가 없는 질문에서 무리하게 답하는지도 확인합니다. 이후 다른 설비군으로 나누어 성능이 유지되는지 확인해야 확산을 판단할 수 있습니다. 절감 효과는 실제 조회 횟수와 측정한 건당 절감 시간으로 산출하겠습니다. 아직 측정하지 않은 비용 절감률이나 고장 감소율을 성과로 제시하지 않겠습니다.

- **왜 더 좋은 기존 모델을 쓰지 않습니까?** 이번 개발 질문에서는 기존 Qwen이 우세했습니다. 최신 모델이라는 이유로 채택하지 않고, 사용하지 않은 현장 질문에서 재비교한 뒤 운영 모델을 판단하겠습니다.
- **Clef가 거짓 답변을 막습니까?** Clef는 후보 순서를 보완합니다. 사실 검증은 원문·인용 검사와 사람의 원문 확인을 함께 사용하며 모든 의미 오류가 해결된 상태는 아닙니다.
- **사업 효과와 특허는 있습니까?** 공개 가능한 양산 성과·절감액·특허 출원등록 자료는 확인하지 못했습니다. 시범 운영에서 탐색 시간과 잘못된 조치 안내를 측정하고, 특허성은 별도 선행기술 조사로 판단해야 합니다.

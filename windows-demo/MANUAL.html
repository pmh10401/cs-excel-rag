  1. Windows에서 setup.bat guard를 한 번 실행해 선택 라이브러리와 고정 모델을 준비합니다. 인터넷 연결과 다운로드 공간이 필요합니다.

기본은 꺼짐입니다. 결과 기록은 기존 답변을 유지하며 경고를 표시합니다. 답변 차단은 지지 부족을 최대 한 번 보정하고 재실패하면 답변을 거절합니다. 번역·모델·시간·512토큰 입력 한도 오류는 검사 불가로 구분합니다. 원문을 자르거나 DB를 변경하지 않습니다.

LLM 답변 → 프로그램 원문·인용·숫자 검사 → LLM이 주장과 인용 셀을 따로 영어 번역 → mDeBERTa 판단 → 표시 또는 보정·차단

모델 지지 점수 기준 0.8은 업무 정확도나 사실의 확률이 아닙니다. 올바른 문장도 거절될 수 있으므로 먼저 결과 기록으로 업무 오류·지연을 확인하세요. 질문 중 모델을 다운로드하지 않으며, 준비된 모델을 로컬 CPU에 적재해 재사용합니다. 설정의 모델 준비 단추는 다운로드·적재용이며 라이브러리 설치를 대신하지 않습니다. 설치 확인 명령 .venv\Scripts\python.exe -m ragkit.claim_verification --check는 계산 동작 확인이며 업무 품질 인증이 아닙니다.

1. 설치와 실행 순서

Windows x64용 Python 3.14와 py launcher를 준비하고 ZIP 전체를 C:\RAG\RAG-Windows-GPT4 같은 폴더에 압축 해제하세요. 전달받은 파일이 .TXT이면 확장자를 .zip으로 바꾼 뒤 압축을 해제하세요. ZIP 내부에서 실행하지 마세요.

  1. start.bat을 실행합니다. 처음에는 setup.bat으로 설치·검사를 진행한 뒤 웹 UI를 엽니다.
  2. 자료에서 Excel 전체 경로와 읽기 방식을 선택하고 입력 검사 → DB에 추가·갱신 → DB 문장 다듬기를 실행합니다.
  3. 문장 검토에서 수정문 채택·원문 유지·직접 편집을 선택하고 검토 저장을 누릅니다.
  4. 질문에서 질문하고 근거 셀을 확인합니다.

검토 저장은 DB에 바로 반영됩니다. JSON 파일을 다운로드하거나 다시 넣을 필요가 없습니다. 기존 콘솔 메뉴는 .\.venv\Scripts\python.exe demo.py --menu로만 엽니다. 아래 메뉴 번호·CLI 비교 설명은 이 구형 콘솔을 뜻합니다.

자료 준비 중 질문 · 2026-10-13

문장 다듬기·번역·벡터·여러 파일 등록·야간 실행 중에도 질문 화면에서 기존 자료에 질문할 수 있습니다. 현재 모델 요청이 끝나면 질문을 우선 처리하고, 다음 질문 사이에 자료 요청도 진행합니다. 질문과 자료 준비의 상태·실패 상세를 각각 표시하며 야간 작업의 저장 후 중지도 사용할 수 있습니다.

검색할 때 읽은 원문으로 답변과 인용을 검사하므로 중간에 DB가 바뀌어도 근거는 유지됩니다. 긴 DB 저장 구간과 이미 실행 중인 모델 요청 동안에는 대기할 수 있습니다. Mac 가상 자료·모의 모델·브라우저로 확인했으며 Windows 실제 서버의 속도와 업무 정확도는 별도 검증 대상입니다.

자료 준비 복구 · 2026-10-13

여러 파일 등록·야간 실행의 상태를 출력 폴더의 jobs.sqlite3에 저장합니다. start.bat으로 서버를 다시 실행하면 성공분을 재사용해 이어갑니다. 중지 요청이나 실패 기록은 자료 → 자료 준비 복구에서 확인하고 이어서 실행 또는 복구 대기 해제를 선택하세요. 대기 해제는 저장한 원문·검토를 삭제하지 않습니다. 아직 등록하지 못한 DRM 파일은 서버 Excel에서 인증 후 열어 두세요.

개별 처리 버튼과 질문·대화의 자동 복구는 후속 범위입니다. Windows 실기기 검증은 별도입니다.

새 접수번호는 누적 추가하고 동일 원문은 재사용합니다. 같은 원본에서 수정한 접수는 갱신하고 재검토로 표시하며, 다른 파일의 같은 접수번호와 내용이 다르면 등록을 중단합니다. 이번 파일에 없는 기존 접수는 삭제하지 않습니다. 등록 건수와 원문을 확인하고 프로그램 종료 후 출력 폴더를 백업하세요.

임베딩 자동 준비와 생성

2026-10-07 새 배포본은 text-embedding-embeddinggemma-2를 사용합니다. LM Studio 런타임 업데이트·EmbeddingGemma 2 Q8_0 다운로드·설정을 마쳤다면 다음부터 start.bat만 실행하세요. 로컬 임베딩 서버·모델을 확인하고 필요할 때 시작합니다. 저장된 DB의 누락 벡터를 이어서 생성하고 DB 등록·변환·검토 저장 후에도 변경분을 자동 갱신합니다. 자료 화면에서 준비 상태·실패 이유를 확인합니다. 질문은 키워드 + 벡터 검색으로 시작합니다.

임베딩 실패가 이미 저장한 파일·문장·검토를 취소하지는 않습니다. 다음 시작 또는 벡터 생성 버튼으로 남은 자료를 재시도합니다. 기존 config.json을 유지하면 이전 모델도 유지됩니다. 교체 전 설정을 백업하고 embedding 부분만 새 배포본과 맞춘 뒤 재시작하세요. 문서 접두사는 title: none | text: , 질문 접두사는 task: search result | query: 이며 마지막 공백을 포함합니다. 새 벡터는 768차원이고 모델 로드 문맥은 8192토큰입니다. 원문·검토·Qwen 벡터는 보관하며 새 프로필에 벡터를 생성합니다. Windows 실기기 검증은 별도입니다. embedding.auto_start를 false로 지정하면 로컬 서버 자동 시작을, auto_index를 false로 지정하면 자동 벡터 생성을 끕니다. 원격 임베딩 서버는 자동 실행하지 않습니다.

반복 실험용 입력 변환

현재 단계·시트 처리 행 수·변환 건수·경과 시간을 표시합니다. 진행률은 현재 단계 기준이며 전체 행 수를 모를 때는 대기 막대를 표시합니다. 빈 행은 처리 행 수에 포함되지만 변환 건수에서는 제외합니다. 압축 파일 저장까지 끝나야 100%가 됩니다. DRM 읽기가 멈춘 것처럼 보이면 Excel 셀 편집을 Enter로 확정하거나 Esc로 취소하고 열린 대화상자를 처리하세요.

자료 화면에서 Excel 경로를 입력하고 실험용 파일로 변환을 누릅니다. 출력 폴더의 inputs/파일명.rag.jsonl.gz에 원문을 저장하고 변환 파일을 자동 선택합니다. 이후 문장 다듬기·검토·질문은 해당 파일로 진행합니다. 변환은 모델을 호출하지 않으며 원문·자료형·셀 주소와 기존 검토 연결을 보존합니다.

다음 실행에서는 변환 파일의 전체 경로를 입력하세요. 압축을 풀 필요가 없으며 Excel을 닫아도 됩니다. DRM 파일은 첫 변환 때 Windows Excel에서 인증하세요. Excel 내용이나 열 대응을 바꿨다면 원본을 다시 선택해 변환합니다. 변환 파일에는 변환 당시의 원문이 보관됩니다.

서버 설정

사용자가 알려 준 Windows 실제 모델은 gpt-oss-120b입니다. 요청 모델 이름 gpt-4는 기존 호환 서버 설정을 유지한 값이며 실제 서버가 다른 이름을 요구하면 변경하세요. Mac 기능 검증은 Qwen 27B를 사용합니다.

config.json에 사용자가 확인한 주소와 옵션을 유지합니다.

{
  "base_url": "http://23.43.51.216:6100/v1",
  "api_key": "EMPTY",
  "model": "gpt-4",
  "reasoning_effort": "high",
  "timeout_seconds": 600
}

대기 제한은 API 요청 한 건 기준입니다. Windows 경로는 임베딩 모델·학습·LM Studio를 요구하지 않습니다. 설치에는 패키지 저장소 연결이, 실제 처리에는 지정한 서버 연결이 필요합니다. 다듬을 문장과 필요한 문맥, 답변용 검색 근거가 해당 서버로 전송됩니다.

브라우저를 닫아도 처리는 계속되며 같은 출력 폴더로 서버를 다시 실행하면 완료 파일을 건너뛰고 이어갑니다. 등록이 끝나면 필요한 벡터를 한 번 갱신하며, 문장 다듬기와 야간 자동 실행은 그 다음에 누릅니다.

  2. 같은 Windows 계정으로 데스크톱 Excel에서 DRM 파일을 먼저 엽니다. 인증과 대화상자를 처리하고 CSList 또는 19~26년 누적_260925 시트의 값이 보이도록 둡니다.
  3. start.bat의 자료에서 전체 경로와 Windows Excel에서 열린 파일을 선택합니다.
  4. 입력 검사를 실행한 뒤 문장 다듬기로 진행합니다.

일반 파일은 읽기 방식 일반 파일(openpyxl)로 읽습니다. 최초 샘플도 openpyxl을 사용합니다. 선택한 방식은 다음 실행에도 유지됩니다. 같은 파일이 여러 Excel 프로세스에 열려 있으면 하나만 남겨 주세요.

프로그램은 현재 열린 셀 값을 읽습니다. 저장하지 않은 편집 내용도 포함될 수 있으므로 읽는 동안 편집하지 마세요. 파일을 새로 열거나 저장·닫기, Excel 종료, 보안 설정 변경을 하지 않습니다. 수식은 Excel에서 계산이 완료된 숫자·날짜·문자 값으로 읽습니다. 계산 중이거나 대기 중이면 F9로 계산을 마친 뒤 다시 실행하세요. 수식 문자열 대신 읽은 시점의 값·자료형·셀 주소를 보관하며, 프로그램이 계산·외부 링크 갱신을 실행하지 않습니다. 실제 오류 값과 병합 셀은 거절합니다.

DRM 정책이 COM 자동화 읽기를 막으면 오류로 중단합니다. 실제 Windows·Excel·DRM 환경에서 연결 여부를 확인해야 합니다. 별도의 xlwings Excel 추가 기능은 필요하지 않습니다. 공식 설치 안내

모델을 호출하지 않고 연결과 원문 검색만 시험하려면:

.\.venv\Scripts\python.exe demo.py --schema cslist_schema.json --reader xlwings --excel "C:\자료\업무기록.xlsx" --sheet CSList --search-only --question "배기 튜브 조치는?"

2. CS Excel 준비

cslist_sample.xlsx는 CSList 시트에 128열과 가상 기록 8건을 담고 있습니다. 열 이름은 제공된 CS 양식을 기준으로 합니다. 실제 업무 사례를 익명화한 자료가 아닙니다.

  • 첫 행에 cslist_schema.json의 128개 열 이름을 정확히 넣습니다. 열 순서는 바꿔도 됩니다. 프로그램은 실제 셀 위치를 기록합니다.
  • 한 행은 하나의 CS 접수번호를 가집니다. 번호는 고유한 문자열이어야 합니다. 별도 id 열을 추가하지 마세요.
  • 같은 접수번호가 여러 행이면 오류로 알려 줍니다. 자동으로 합치거나 임의 번호를 만들지 않습니다.
  • CS 입력 시트는 CSList를 사용합니다. 메뉴에서 시트 이름을 따로 묻지 않습니다.
  • 빈 셀은 그대로 두어도 됩니다. 빈 값과 0은 다릅니다. 숫자·날짜의 자료형도 저장합니다. 완전히 빈 행은 건너뛰며, 접수번호만 있는 행은 오류입니다.
  • 일반 파일 방식은 수식을 계산하지 않습니다. 수식이 있다면 Windows Excel에서 계산을 마치고 Excel 연결로 읽으세요. 실제 오류 값·병합 셀과 암호화/DRM 해제는 지원하지 않습니다. 숨긴 행과 필터로 가린 행도 읽습니다.

3. 문장 검토와 저장

수정할 문장은 접수·작업별로 표시되고, 보호하는 값은 보존 열 보기를 펼쳐 확인합니다. 원본 128열 표도 펼쳐 볼 수 있습니다. 각 셀의 주소를 표시하며 빨간 취소선은 삭제, 초록 밑줄은 추가입니다.

선택검색에 반영되는 내용

직접 편집원문과 직접 고친 문장을 함께 사용합니다.

웹 UI에서는 현재 접수의 셀을 여러 개 선택하거나 현재 접수 전체 선택을 누른 뒤 수정문 일괄 채택 / 원문 일괄 유지를 적용합니다. 검토 저장을 누르면 개별 편집을 포함한 현재 접수의 변경 셀 모두를 함께 저장합니다. 다른 접수와 보존 열·빈 셀은 바뀌지 않습니다. 제안 없는 셀을 선택하면 일괄 채택은 비활성화됩니다. 검사에 하나라도 실패하면 전체 저장을 거절합니다.

2,000건 등 현재 자료 전체 채택

문장 검토 → 현재 자료 전체 처리 → 미검토 제안 전체 채택·저장을 누르면 검색 조건·페이지와 관계없이 현재 DB 전체의 미검토 제안을 채택하고 저장·검색 반영까지 끝냅니다. 기존 채택·원문 유지·직접 편집·재검토 대상은 보존합니다. 빈 셀·보존 열은 제외하고 제안 없는 접수와 검사 실패 접수는 건너뛰어 건수·오류를 표시합니다. 화면에서 변경한 검토가 있으면 먼저 저장하세요.

Excel과 DB 원문이 같아야 하므로 DRM 파일은 Excel에서 열어 둡니다. LLM을 다시 호출하지 않습니다. 검토·색인 저장이 실패하면 채택도 복구하며, 다시 누르면 남은 미검토 제안만 처리합니다. 문장 다듬기 중 일부 실패한 작업의 중간 결과는 전체 정리 성공 후 검토 대상으로 전환됩니다.

검토 저장을 누르면 DB에 직접 반영됩니다. 문장 다듬기에서 검사를 통과한 JSON은 자동 중간 저장되며, 사용자는 화면에서 채택 여부만 선택합니다. 저장 전에 화면을 닫거나 새로고침하면 저장하지 않은 선택은 사라질 수 있습니다.

초기 정적 HTML·콘솔 방식만 검토 JSON 파일을 전달했습니다. 기본 웹 UI에서는 이 절차를 거치지 않습니다.

  • 빈 셀에 정상·미실시 같은 사실을 새로 넣지 않았는가?

잘못된 열·숫자·빈칸 변경 등을 검사하고, 실패하면 오류를 알려 한 번 보정을 요청합니다. 계속 실패하면 해당 행의 오류를 기록하고 나머지 행을 계속 처리합니다. 형식 검사를 통과해도 뜻이 정확하다는 보장은 없습니다. 원본 Excel은 덮어쓰지 않으며 수정문은 DB에 저장합니다.

4. 검색 자료의 구조

근거 부족은 검색 후보는 있지만 모델이 질문에 답할 관련 근거가 없다고 판단한 상태입니다. 예를 들어 펌프 소음 질문에 누수 기록만 검색된 경우입니다. 전체 DB에 기록이 없다는 뜻은 아니며, 설비명·부품명·발생 조건을 보완해 다시 검색할 수 있습니다. 관련 사례의 일부 셀이 비어 있거나 특정 접수의 빈 항목만 물어도 미기재로 답하도록 요청합니다. 빈칸과 0을 구별합니다. 웹 답변은 모델의 설명과 인용 번호만 표시합니다. 직접 인용한 셀은 접수별 인용 근거에서, 그 외의 조치·결과 셀은 접힌 추가 참고 원문에서 확인합니다. 같은 셀은 한 번만 표시하며 관찰 시간·실패·재발·미실시 원문은 보존합니다. 추가 모델 호출이나 DB 재생성은 필요하지 않습니다. 잘못된 JSON·인용·수치의 근거 검사 실패는 계속 오류로 구분합니다.

현상·알람·설비·조치를 나눈 검색 색인에서 현상과 알람을 우선합니다. 소음/이상음/noise, 누수/누설/leak/leakage, 진동/vibration을 연결합니다. 이 증상과 펌프/pump 또는 팬/fan을 함께 입력하면 둘 다 언급된 접수만 찾습니다. 여러 증상은 그중 하나를 포함한 기록을 찾고, 접수번호를 명시하면 해당 접수 전체를 조회합니다. “소음 없음”도 관련 기록이므로 일치 자체가 발생·해결을 뜻하지는 않습니다. 다른 동의어나 한 접수 안 여러 장비의 관계는 자동으로 판단하지 않습니다.

업데이트 후 질문·검토 저장 시 검색 색인만 자동 갱신합니다. 원문·제안·채택 이력을 보존하고 실패하면 이전 색인으로 복구합니다. 문장 다듬기를 다시 실행하면 새 프롬프트로 제안을 재생성합니다. 증상·조건·재발·미교체를 보존하는 새 평가 3건은 .\.venv\Scripts\python.exe evaluate.py --start 75 --limit 3으로 실행합니다.

증상으로 질문하면 과거 현상 → 당시 조치 → 관찰 결과·한계를 접수별로 답합니다. 예: “진공 알람이 반복됩니다. 과거 조치 사례와 관찰 결과를 찾아주세요.” 실패한 조치, 재발·장기 미확인, 예정·미실시를 구분하며 현재 설비에 그대로 시행하라는 지시로 바꾸지 않습니다.

Windows는 GPT-OSS 120B 기준 max_tokens=131072, context_window=131072를 사용합니다. 실제 요청에서는 문맥 한도에서 입력 JSON의 UTF-8 바이트 수와 여유 1,024를 뺀 값으로 출력 한도를 낮춥니다. 서버의 실제 로드 문맥이 더 작으면 context_window도 낮춰야 합니다. 기존 config.json에는 두 값을 반영하고 앱을 다시 실행하세요. answer_max_tokens가 있으면 답변에 우선 적용합니다. temperature=1, top_p=1, 추론 high를 유지하며 입력 근거의 24,000자 제한은 별도입니다. 원문 인용은 모델이 선택한 셀 주소에 프로그램이 원문 전체를 붙입니다. 답변이 출력 한도에서 잘리면 같은 근거·설정으로 한 번 재요청하며 검사 보정을 포함해 최대 두 번 호출합니다.

접수 한 건을 문서 하나로 검색하고, 문서 안에서 접수·작업1·작업2의 원문과 근거 ID를 구분합니다. 각 작업의 원인·조치·부품을 함께 유지합니다. 값이 모두 비어 있는 작업은 만들지 않습니다.

SQLite FTS5는 Kiwi로 조사·어미를 구분한 단어를 우선 검색하고 BM25 점수로 상위 3개를 찾습니다. 예를 들어 “냉각수를”는 “냉각수”로 검색하며 “니다” 같은 어미는 제외합니다. keywords에는 단어를, grams에는 보조 두 글자 조각을 저장합니다. 단어 검색이 비었을 때만 보조 검색하며 모든 질문 단어의 조각이 순서대로 맞아야 합니다. 검색 점수는 정답 확률이 아닙니다.

“물이 샙니다/샌다/새요”는 누수·누설, “웅웅/윙윙/달그락”은 소음·이상음, “떨림/떨려요”는 진동 관련 후보를 찾습니다. 키워드 + 벡터 결합 검색에서 “송풍기”는 fan, “뜨겁다”는 온도·고온, “대기압으로 복귀/돌아오다”는 vent·벤트도 키워드 후보로 찾습니다. 원래 질문은 유지하고 키워드 단독 검색, 코드·날짜 정확 조회와 영어를 함께 쓰는 검색에는 추가하지 않습니다. 이 보완은 앱 재시작으로 적용되며 재색인·벡터 재생성은 필요 없습니다. 정상·부정 조건은 원문을 대조하세요. 검색 표현 확장은 원문 인용 검사와 분리하며 원인·해결 여부를 확정하지 않습니다. 등록한 표현 밖의 의미 검색과 “무상 자재 금액이 0인가요” 같은 수치 열 조건 질문은 정확성을 보장하지 않습니다.

업데이트는 앱을 닫고 setup.bat → start.bat 순서입니다. Kiwi 사전은 설치 시 내려받고 이후 로컬에서 사용합니다. 다음 질문·검토 저장 시 색인을 자동 갱신하므로 문장 다듬기를 다시 할 필요는 없습니다. check.bat에 한국어 검색 검사도 포함됩니다.

rag_documents / rag_original_documents원문+채택문 / 원문만으로 만든 접수 문서 색인

주장마다 실제 작업·열·원문 셀 전체를 연결하고 숫자와 대표 단위를 검사합니다. 원문 셀 일치가 의미의 정확성을 보장하지는 않으므로 펼쳐서 대조하세요. 모델 입력은 기본 24,000자로 제한하고 초과하면 질문 범위를 좁히도록 안내합니다.

원문·채택문 검색 비교

7번 메뉴에서 평가 질문 JSON 경로를 입력합니다. 기본 샘플은 cslist_cases.json입니다. 같은 DB와 질문, 문서 단위, 상위 3개 기준으로 비교하며 모델을 호출하지 않습니다. 결과는 search_comparison.html과 search_comparison.json에 저장됩니다.

채택문이 원문과 같으면 다듬기의 효과를 평가할 수 없다고 표시합니다. 화면의 가독성·의미 유지 평가를 선택해 다운로드할 수 있습니다. 품질 평가는 DB의 채택 선택을 바꾸지 않습니다.

정확한 건수 질문

전체 접수는 총 몇 건인가요? 또는 설비코드="DEMO-ETCH-01" 접수는 몇 건인가요?로 질문합니다. 현재 입력 파일·시트의 전체 원본을 SQL로 집계하며 검색 결과 3개를 세지 않습니다. CS 접수번호·설비코드·접수일자·고객사명·제품군·유/무상 열의 명시적 동등 조건만 지원합니다. 같은 열의 복수 조건과 자연어 기간·재발·완료 조건은 임의 해석하지 않습니다.

저장된 자료로 질문

4번 메뉴는 문장 다듬기를 다시 호출하지 않습니다. DB에 등록된 원문을 사용하므로 Excel을 삭제해도 됩니다. 파일 수정은 재등록한 뒤 반영됩니다. required와 forbidden 평가 규칙은 수치 누락·예정/완료 혼동 같은 알려진 오류의 회귀검사입니다. 실패하면 결과를 보관하고 실패로 종료합니다. 기준은 모델에 보내지 않습니다.

한국어 원문과 영어 질문

  1. 질문 → 영어 번역 질문 함께 사용은 기본으로 켜져 있습니다. 한국어 질문 전체를 한 번 번역해 원문과 함께 답변 모델에 전달합니다. 답변의 영어 번역 질문 확인에서 번역문을 펼쳐 볼 수 있습니다.
  2. 영어 키워드 검색도 사용하려면 자료 → 영어 검색 자료 → 남은 자료 중 20건 → 영어 변환 / 이어서 실행으로 문서를 준비합니다. 검색 방식과 후보 비교에서 후보 접수를 확인합니다.
  3. 질문 옵션을 끄고 같은 질문을 실행해 관련 사례, 조치별 결과, 부정·미실시·관찰 조건, 응답 시간을 비교하세요. 품질 상승은 보장되지 않습니다.

영어 문서가 없어도 질문 번역을 답변에 사용할 수 있으며 별도 모델 설정이나 문서·벡터 재생성은 필요하지 않습니다. 영어 색인이 있으면 같은 번역을 키워드·결합 검색에 재사용합니다. 벡터 질의와 정확한 코드·날짜 검색은 원문을 사용합니다. 영어 질문은 다시 번역하지 않고 건수 집계에는 번역을 하지 않습니다.

번역이 비었거나 잘렸거나 숫자·부호·단위·식별자 검사에 실패하면 원문 질문만으로 계속 처리합니다. 두 언어가 충돌하면 한국어 질문을 우선합니다. 번역은 사실 근거가 아니며 답변과 인용은 원래 언어의 원문 셀을 기준으로 합니다. 보정 요청과 자동 문맥 계산에도 같은 질문 번역을 사용합니다.

문서 영어 변환은 제목·현상·원인·조치 등 현재 원문 또는 검토한 텍스트를 대상으로 합니다. 원본 128열 또는 28열·검토 이력·셀 위치는 유지하며 빈칸과 미채택 제안은 제외합니다. 문서 번역은 별도 DB 테이블에 저장하고 변경된 셀은 다시 변환합니다. 동시 처리 수는 문장 다듬기와 같으며 기본 200, 최대 1,000입니다. 질문 번역은 문서·검토 이력을 변경하지 않습니다.

번역 검사는 의미 전체의 정확성을 보장하지 않습니다. Windows 출력 토큰은 공통 131,072 상한과 입력 예약량 차감을 적용합니다.

5. 질문과 시험

메뉴 4번에 “DEMO-ETCH-01의 배기 튜브 조치 결과는?” 같은 질문을 입력합니다. 답변의 접수번호·작업번호와 펼쳐 볼 수 있는 원문 근거를 확인하세요. 저장된 원문으로 답변만 요청합니다. Excel 원문이 달라지면 2번 메뉴로 갱신해야 합니다.

cslist_cases.json에는 가상 질문 10개, 기대 근거, 사람이 확인할 기준이 있습니다. 기본 샘플로 전체를 시험하려면 프로그램 폴더의 PowerShell에서:

.\.venv\Scripts\python.exe demo.py --schema cslist_schema.json
Start-Process ".\cslist-output\demo.html"

실제 서버를 호출합니다. 자신의 파일로 여러 질문을 시험하려면:

.\.venv\Scripts\python.exe demo.py --schema cslist_schema.json --excel "C:\자료\CS목록.xlsx" --sheet "CSList" --cases "my_cases.json"

my_cases.json은 아래처럼 작성합니다. 기대 근거와 검토 기준은 모델에 보내지 않습니다.

[
  {
    "question": "DEMO-ETCH-01의 배기 튜브 교체 결과는?",
    "expected_ids": ["CS-DEMO-001/작업2"],
    "review": "60분 관찰 중 알람이 없었으나 장기 재발은 미확인이다."
  }
]

--search-only를 추가하면 API 없이 원문 검색만 검사합니다. 임시 DB를 사용하므로 저장된 검토문 평가나 HTML 생성은 하지 않습니다. 기대 ID가 빈 목록이면 기본적으로 검색 점수를 매기지 않습니다. "expect_no_match": true를 함께 지정하면 검색 결과가 없어야 통과합니다.

check.bat은 입력·검토 저장·작업 분리·샘플 15개 질문 검색·모의 전체 실행을 검사합니다. 실제 모델의 가독성이나 답변 정확도는 별도로 확인해야 합니다. 문장 다듬기 평가 77건은 프로그램 폴더의 PowerShell에서 .\.venv\Scripts\python.exe evaluate.py로 실행할 수 있습니다.

7. 문제 해결

입력 오류가 나면 자료 등록을 자동으로 펼치고 알림으로 이동합니다. 파일명·시트명·셀 주소·수정 방법을 확인하세요.

  • A1, B1: 중복 열 이름 'CS NO': 두 셀의 실제 열 제목을 구분합니다.
  • C1: 열 이름이 비어 있음: C1에 양식의 제목을 입력합니다.
  • AD3에 값이 있지만 AD1에 열 이름이 없음: AD열의 데이터와 제목을 확인합니다.
  • H7: Excel 오류 값 '#VALUE!': H7의 수식·참조를 수정합니다.

제목과 모든 값이 빈 뒤쪽 열만 제외합니다. 중간의 빈 제목이나 데이터가 있는 무제목 열은 자동 삭제하지 않습니다.

추가 품질 검사와 열 연결

웹 UI에서 입력 검사를 누르고, 모르는 열은 양식 열을 선택해 열 대응 저장을 누르세요. 같은 열에 두 원본 열을 합치지 않습니다. 규칙은 결과 폴더의 column_aliases.json에 보관합니다. 문장 다듬기 / 이어서 실행은 성공한 행을 재사용하고 완료·재사용·실패 접수번호를 표시합니다.

병렬 처리 설정과 자동 저장

웹 UI의 설정에서 문장 다듬기·영어 번역 동시 처리 수를 1~1,000건으로 선택하고 저장합니다. 기본값은 200건입니다. 서버 처리 여력에 맞춰 조절하세요. 실행 중에는 변경할 수 없습니다. 선택한 값은 출력 폴더의 cslist_settings.json에 보관합니다.

검사에 통과한 JSON은 완료한 행부터 자동으로 DB에 저장합니다. 모델 요청·검사가 실패한 행을 기록하고 나머지 행은 끝까지 처리합니다. 화면에서 처리·성공·실패 수와 각 오류를 확인합니다. 같은 원본·설정으로 이어서 실행하면 실패한 행만 재시도합니다. 입력 파일·DB 저장 오류는 중단합니다. 수정 제안은 자동 채택하지 않으며 전체 성공 후 검색 자료를 교체합니다.

검토 이후 자동 갱신

설정의 검토 저장 후 영어 자동 갱신을 켜면 검토 반영 후 벡터를 먼저 갱신하고 저장한 접수를 영어로 번역합니다. 실패해도 검토 저장은 유지하며 다음 접수를 처리합니다. 자료 화면에서 실패한 번역만 다시 실행할 수 있습니다.

목록과 상세에서 검토 대기 셀 수·영어·벡터 상태를 확인하세요. 검토 화면은 변경 부분을 강조하며 중요한 표현 변경, 변경된 셀, 현재 접수의 동일 원문·제안을 묶어 볼 수 있습니다. 표시와 묶기는 의미 정확도를 보증하거나 자동 채택하지 않습니다.

검색 평가와 답변 진단

출력 폴더의 answer_diagnostics.jsonl에 질문·응답·검사 오류·보정 결과·호출 시간을 로컬로 남깁니다. 평가 정답은 사람이 지정해야 합니다.

evaluate_search.py는 같은 질문으로 한국어·영어 결합 검색을 비교합니다. workflow_cases.json은 가상 30문항 초안이며 실제 업무 평가가 아닙니다. 영어 자료가 없으면 효과 비교를 생략합니다. 명령과 실제 질문 양식은 README.txt의 마지막 부분을 참고하세요.

벡터 검색과 숫자 보정

벡터 검색에는 별도 임베딩 모델을 사용합니다. 배포본에는 로컬 LM Studio와 Qwen 임베딩 설정이 포함되어 있습니다. 모델 설치를 마쳤다면 start.bat만 실행하세요. 다른 주소·모델을 사용할 때만 config.json의 embedding 설정을 바꿉니다. 답변 모델 gpt-4 설정은 유지합니다.

기본적으로 벡터를 자동 생성·갱신하며 질문 화면은 키워드 + 벡터 검색으로 시작합니다. 자료 화면의 벡터 생성 버튼은 일부 자료 시험 또는 실패분 재시도에 사용합니다. 기존 원문·제안·검토는 보존됩니다.

숫자 검사 오류에는 원문·응답의 숫자 목록을 표시합니다. 첫 숫자 오류는 실패한 셀의 숫자·단위·식별자를 보호해 한 번 보정합니다. 예를 들어 1.SCW132 11.8 STEP에서 목록 번호 1.도 유지합니다. 보정에 실패하면 실패 목록에 남기고 다른 행을 계속 처리합니다.

영어 번역 자동 보완

야간 자동 실행

자료 화면의 1. 자료 등록을 펼쳐 DB 등록을 마친 뒤 자동 채택하고 검색까지 준비를 누르세요. 등록된 DB가 있으면 파일 입력을 접고 원문·벡터·영어 자료 현황과 야간 실행을 먼저 보여 줍니다.

자료 준비 → 문장 다듬기 → 검사 통과 제안 자동 채택 → 벡터 → 영어 번역 → 검색 확인의 6단계를 표시합니다. 실패한 단계는 성공하거나 사용자가 중지할 때까지 60~300초 간격으로 재시도합니다. 인증·요청·DB·색인 오류도 포함하며, 자동 채택에서 거절된 접수는 오류 사유로 다듬기를 보완합니다. 기존 검토·원문·성공 결과는 보존합니다. 실행 전 입력·설정 검증은 유지합니다.

재시도 대기에는 남은 시간을 표시합니다. 시도 횟수와 오류 상세를 펼치면 원인을 확인할 수 있습니다. 진행 막대는 완료한 단계 수이며 시간 비율이 아닙니다. 저장 후 중지는 진행 중인 행·묶음 저장 후 적용되며 서버 응답 제한까지 기다릴 수 있습니다. 실패나 중지를 검색 준비 완료로 표시하지 않습니다.

인증·설정·파일 권한 등 외부 원인이 그대로면 계속 실패할 수 있습니다. 설정 파일 수정은 중지 후 프로그램을 재시작해 적용하세요. 브라우저를 닫아도 실행되지만 프로그램과 모델 서버를 켜 두고 PC 절전을 해제해야 합니다. 프로그램 재시작 후에는 같은 버튼으로 이어서 처리합니다. 등록된 자료는 DRM Excel 없이 처리합니다.

## 원문, 제안, 채택문

원문은 DB의 사실 근거입니다. LLM은 수정 대상 셀만 한국어로 다듬고 누적 양식의 중국어·영어 설명도 한국어로 정리합니다. 빈칸을 추정해서 채우지 않으며 식별자·수치·단위·부호·순서를 검사합니다.

제안은 원문과 별도로 저장합니다. 일반 실행에서는 사람이 **수정문 채택·원문 유지·직접 편집**을 결정하고 검토를 저장합니다. 영어 번역 등에서 쓰는 유효 문장은 채택·직접 편집 값이 있으면 그 값, 없으면 원문입니다. 미채택 제안은 사용하지 않습니다. 검색 문서는 원문과 채택문을 함께 활용합니다.

현재 접수의 여러 셀을 일괄 반영하거나 DB 전체의 미검토 제안을 일괄 채택할 수 있습니다. 기존 검토·직접 편집·재검토 대상은 보존하며 검사 실패를 성공으로 바꾸지 않습니다. 검토 저장과 검색 자료 동기화는 함께 확정하거나 롤백하고, 이후 모델을 호출하는 벡터·번역 갱신은 별도 단계입니다.

## 실패가 전체 진행을 막지 않도록 하는 방법

다듬기는 정상 행을 체크포인트에 보관하고 실패 행 이후에도 처리를 계속합니다. 성공분은 같은 원문·설정으로 재개할 때 재사용하지만, 실패가 남은 전체 결과를 준비 완료로 바꾸지는 않습니다.

정상 종료된 응답의 내용 오류에는 오류 사유를 넣어 한 번 보정합니다. 숫자 오류는 숫자·단위·숫자를 포함한 코드를 보호 표시자로 바꾸어 요청하고 순서·개수를 대조해 복원합니다. 그래도 숫자 보호·보존 오류만 남으면 해당 셀을 원문으로 유지하고 사유를 남깁니다. 이는 다듬기 성공과 구분하며 통신 오류·잘림·다른 형식 오류까지 원문 복귀로 숨기지 않습니다.

영어 번역은 실패 셀만 최신 오류와 함께 최대 세 번 **추가 보완**합니다. 이미 통과한 셀은 다시 번역하지 않고 접수 전체 대상이 통과해야 번역을 확정합니다. 긴 입력은 셀별·안전한 공백 경계로 나누며 안전하게 나눌 수 없으면 실패로 표시합니다. 시간 초과 재시도와 내용 보완 횟수는 별개입니다.

동시 처리 수는 문장 다듬기·영어 번역에서 기본 200, 최대 1,000으로 설정할 수 있습니다. 선택한 전체 처리 건수, 임베딩 배치 크기, 서버의 실제 동시 계산 수와는 다른 값입니다. [야간 실행](운영과-장애대응.md)에서는 남은 실패를 대기 후 다시 처리합니다.

출처: [다듬기](../ragkit/llm.py), [영어 처리](../ragkit/english.py), [야간 처리](../ragkit/overnight.py), [상세 처리 흐름](../docs/전체-프로그램-플로우.md).

## 검색 경로

| 경로 | 역할 | 주의할 해석 |
| --- | --- | --- |
| 한국어 키워드·FTS5 | 단어·현상·코드로 기록을 찾음 | 한글 2그램은 단어 검색이 부족할 때의 보조 조각이며 데이터 훼손이 아님 |
| 영어 키워드 | 유효 문장의 영어 번역을 검색에 활용 | 영어 번역이 원문의 사실 근거를 대체하지 않음 |
| 벡터 | 증상이 의미상 비슷한 문서 탐색 | 유사도는 해결 확률이나 정확도가 아님 |
| 결합 검색 | 키워드·벡터 후보의 순위를 RRF로 결합 | 접수번호·코드·날짜 정확 조회와 구분 |
| 지원하는 건수 집계 | DB에서 계산 | 검색 상위 몇 건으로 전체 건수를 추정하지 않음 |

영어 질문 병용을 선택하면 한국어 질문의 영어 번역을 검색·답변에 재사용합니다. 번역 검사에 실패하면 한국어만 사용합니다. 현재 벡터 질의는 원문 질문이며, 저장한 영어 번역문을 별도로 임베딩하는 경로는 없습니다. 한글을 전부 영어로 바꿔 원문을 없애는 구조도 아닙니다.

출처: [키워드·2그램·집계](../ragkit/search.py), [영어 번역](../ragkit/english.py), [벡터·결합 검색](../ragkit/semantic.py).

## 벡터와 DB 구조

벡터 입력은 제목·현상·장비 및 부품 등의 주요 증상 필드에 있는 원문과 채택문입니다. 원인·조치만 바뀌면 증상 벡터는 달라지지 않을 수 있습니다. 답변에는 검색된 접수 문서에서 해당 원인·조치·원문 셀을 가져옵니다. 변경되지 않은 입력은 벡터를 재사용하고 모델·입력 프로필이 바뀌면 이전 벡터를 제외합니다.

Qwen3 Embedding 0.6B와 답변 모델은 별도입니다. 벡터는 SQLite BLOB, FAISS 색인은 실행 중 메모리에 둡니다. 준비된 로컬 LM Studio는 시작 시 연결·필요 모델 로드·누락 벡터 생성 경로를 사용합니다. 설치·모델 다운로드·최초 설정은 선행되어야 합니다. 벡터가 실패한 결합 검색은 안내 후 키워드로 진행하고 벡터 전용은 오류로 알립니다.

원문·제안은 `normalized_records`, 검토는 `cell_reviews`, 검색은 `rag_documents`·`rag_original_documents`, 번역은 `english_translations`·`english_failures`, 벡터는 `vector_sources`·`vector_embeddings`가 관리합니다. 재개·원문 복귀·버전 확인용 자료도 현재 기능에 필요합니다. 폐기한 작업별 `rag_chunks`와 SQLite가 관리하는 FTS 내부 테이블은 구별해야 합니다.

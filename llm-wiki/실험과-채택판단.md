## 검색 후보 실험

처음 50문항 중 정답이 있는 질문은 44개입니다. 후속 조건 자료 48문항은 16조건을 한국어·영어·중국어로 표현했으며, 정답 있는 36문항도 독립된 36조건이 아닙니다. 10만 건 합성 DB에서 저장한 후보를 재사용했으므로 이 표를 10만 건 전체 검색 속도나 실제 업무 정확도로 해석하지 않습니다.

아래 숫자는 각 방법의 **기존 정답 질문 44개 중 첫 결과 적중**입니다. 상위 3건·5건 지표, 후보 수, 실행 범위는 연결된 원 보고서를 따릅니다.

| 비교 | 첫 결과 적중 | 관찰과 당시 판단 | 근거 |
| --- | --- | --- | --- |
| 기존 검색 | 40/44 | 비교 기준 | [GLiNER 최초](../docs/GLiNER-실험-20260926.md) |
| GLiNER 증상 태그 10% 가점 | 38/44 | 상위 3건 정답 포함도 44→42로 감소, 미도입 | [최초 결과](../docs/GLiNER-실험-20260926.md) |
| GLiNER 직접 관련성 정렬 | 39/44 | 상위 3건 정답 포함 39/44, 미도입 | [추가 비교](../docs/GLiNER-추가실험-20260926.md) |
| 질문·사례 영어 번역 후 GLiNER 직접 정렬 | 41/44 | 상위 3건에서는 42/44, 조건 검사 개선이 일관되지 않아 미도입 | [영어 비교](../docs/GLiNER-영어번역-실험-20260926.md) |

LEV·CLM 비교는 전체 98문항 중 정확 검색·빈 결과 6문항을 보존하고 나머지 92문항의 976후보 쌍을 평가했습니다. ‘건너뜀’과 ‘실패·누락’을 구분합니다. 관련 확률은 자동 조치 승인이나 사실 확인 점수가 아닙니다.

### 장치와 속도를 해석하는 방법

LEV는 PyTorch MPS에서 실제 실행했습니다. CLM은 먼저 CPU·GPU 확률 차이가 허용치를 넘은 실행을 중단했고, CPU 적재·FP16 변환 후 GPU로 옮긴 경로에서 장치 대조와 전체 평가를 완료했습니다. 실패 기록을 성공 결과로 덮어쓰지 않았습니다.

기존 모델 호출 44문항의 관련성 판단 평균은 LEV 49.373초, CLM 3.479초, Ollaya/Laya 2.590초였습니다. 모델·실행 방식이 서로 다르고 번역·검색·답변을 모두 포함한 서비스 시간이 아닙니다. Ollaya 실측은 **ONNX CPU·F32**이며 Core ML 가속 성공으로 표현하지 않습니다.

## 어떤 조치를 고를지에 대한 별도 실험

검색 순위 실험과 다른 합성 24문항·48조치 후보로 조건 일치와 정상화 결과를 확인했습니다. 적절한 후보가 있는 질문은 16, 보류해야 하는 질문은 8개였습니다.

- `laya:en`: 전체 판단 16/24, 잘못된 추천 8건.
- 같은 자료의 `laya:typed-decisions`: 전체 판단 13/24, 잘못된 추천 11건.
- 여섯 질문과 고정 확률 기준: 개발 자료와 새 평가 자료 모두 추천을 전부 보류. 새 자료에서 답해야 할 12문항을 모두 놓쳤으므로 개선으로 인정하지 않음.

예정·미실시·결과 미기재·부분 개선·짧은 관찰·재발·복합 조치의 개별 효과를 구별해야 한다는 교훈입니다. 실행 오류가 0이라는 결과가 추천의 정확성을 뜻하지 않습니다. 자동 추천에는 연결하지 않았습니다.

## 공통 판단 규칙

평가 전 질문·후보·번역·기준을 고정하고 학습·개발 자료와 새 평가 자료를 구분합니다. 결과를 본 뒤 기준을 바꿔 같은 표본을 다시 합격시키지 않습니다. 실패·잘림·누락은 정답 없는 질문에 대한 올바른 보류와 별도 집계합니다.

실험 코드는 `experiments/`, 요약 보고서는 `docs/`에 있으며 원시 결과·프로토콜·체크포인트·해시는 각 보고서가 지정한 로컬 `outputs/`에 보관합니다. 과거 실행을 검산할 때는 당시 코드·설정·자료가 필요합니다. 새 실행은 새 출력 폴더를 사용하고, 예전 프로토콜의 해시를 현재 코드에 맞춰 고치지 않습니다.

Windows 120B·실제 업무 자료·동시 사용자 규모에 대한 새 품질 측정은 별도 과제입니다. [다음 검증](결정과-다음검증.md)에서 우선순위를 확인합니다.

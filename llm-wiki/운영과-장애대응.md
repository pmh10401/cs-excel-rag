## 시작하기

Windows 전달 파일은 `RAG-Windows-CS128-YYYYMMDD-HHMMSS.TXT`이며 내용은 ZIP입니다. 이름의 날짜·시각은 한국 시간입니다. `.zip`으로 바꿔 전부 압축 해제하고 Python 3.14 x64·`py` launcher를 준비합니다.

| 파일 | 언제 사용하는가 |
| --- | --- |
| `start.bat` | 평소 실행. 첫 실행 시 필요한 설치를 호출하고 웹 UI를 엶 |
| `setup.bat` | 설치·패키지 갱신이 필요할 때. 가상환경·pip 업데이트·의존성·오프라인 검사 |
| `check.bat` | 설치된 환경의 검사를 별도로 실행할 때 |

자료의 **입력 검사 → DB에 추가·갱신 → DB 문장 다듬기 → 문장 검토·저장 → 질문** 순서로 사용합니다. 웹 UI에서는 검토 JSON을 다운로드해 다시 입력할 필요가 없습니다. 기존 콘솔·정적 보고서 경로와 구분합니다.

Mac에서는 예제 설정과 의존성을 준비한 저장소 루트에서 실행합니다.

```sh
.venv/bin/python cs_rag.py --ui
```

기본 웹 주소는 `http://127.0.0.1:8765/`입니다. 업데이트 시 기존 설정과 출력 폴더를 보존하고 프로그램을 재시작합니다. UI와 CLI가 같은 DB를 쓰려면 같은 `--output`을 지정합니다. Mac UI 기본 폴더는 `outputs/mac-cslist-ui`, Windows UI는 `cslist-ui-output`입니다.

## 다른 PC와 모델 연결

`web_host`는 웹 UI가 듣는 주소이고 `base_url`은 답변 모델 API입니다. 임베딩은 `embedding.base_url`·모델·인증을 별도로 설정합니다. 웹을 다른 PC에서 열기 위해 답변 모델 주소를 바꾸는 것이 아닙니다.

웹 연결은 실제 서버의 인터페이스·허용 호스트·방화벽을 함께 확인해야 합니다. 여러 브라우저의 질문은 세션별로 분리하여 대기열에서 순차 처리합니다. 다듬기 동시 처리 수를 높였다고 여러 사용자의 답변도 그 수만큼 동시에 생성되는 것은 아닙니다.

현재는 사용자 로그인·역할별 권한을 갖춘 서비스로 검증되지 않았습니다. 신뢰할 내부 사용자 범위에서 사용하고 대외 공개는 별도 설계가 필요합니다. 세션 분리와 Host·Origin·CSRF 검사는 사용자 인증을 대신하지 않습니다.

출처: [웹 서버·접속 검사](../ragkit/web.py), [다중 사용자 검사](../tests/test_multiuser.py), [시범 운영 한계](../docs/임원보고서.md).

## 야간 실행

DB 등록 후 **자동 채택하고 검색까지 준비**를 누르면 문장 정리 → 검사 통과 미검토 제안 자동 채택 → 벡터 → 영어 검색 자료를 준비합니다. 기존 채택·원문 유지·직접 편집은 보존합니다. 임베딩 설정이 없다면 벡터 생략 상태를 표시합니다.

실패가 남으면 최신 오류를 반영하고 60초부터 최대 300초까지 간격을 늘려 다시 시도합니다. 성공 체크포인트·번역·벡터는 재사용합니다. **저장 후 중지**는 진행 중 작업을 저장한 뒤 새 요청을 멈추며 모델 서버의 응답 제한까지 기다릴 수 있습니다. 서버 종료·PC 재시작 뒤에는 버튼을 다시 눌러야 합니다.

검사 통과 자동 채택은 사람의 의미 검토와 같지 않습니다. 인증·서버 주소·파일 권한 등의 원인이 남으면 반복 실패할 수 있고 다음 날 완료를 보장하지 않습니다. 아침에는 진행 상태가 실제로 **검색 준비 완료**인지 확인합니다.

출처: [야간 실행](../ragkit/overnight.py), [상세 흐름](../docs/전체-프로그램-플로우.md), [야간 검사](../tests/test_overnight.py).

## 오류를 볼 때

| 증상 | 먼저 확인할 것 |
| --- | --- |
| Excel 읽기가 오래 대기 | 셀 편집·대화상자·계산 상태, 현재 처리 단계. 행 수만으로 장애 판단하지 않음 |
| 누락·추가 열 또는 빈 제목 | 파일·시트·셀 주소와 열 대응. 수식 계산값은 Excel 연결 방식 확인 |
| 숫자·단위 짝이나 순서 오류 | 원문·수정문·오류 목록. 검사 해제 대신 보정 또는 원문 유지 사유 확인 |
| 영어가 없거나 너무 길다는 오류 | 번역 대상 유효 문장, 빈 응답·잘림·JSON·길이 구분, 실패 셀 재요청 기록 |
| 답변 근거 검사 실패 | 질문, 실패 응답, 선택 ID·열·날짜·수치, 실제 인용 셀. 정보 부족과 실행 실패를 구별 |
| 보정 요청이 한도를 넘음 | 최근 코드 적용 여부, 최초 근거 분량, 자동 참고 사례 수, 실제 서버 적재 문맥 |
| 임베딩 실패 | 답변 모델과 다른 임베딩 모델 ID·서버 연결·자동 준비 상태 |
| `demo.sqlite3` PermissionError | 정확한 경로·오류 끝부분, 사용 중 연결과 임시 검사 DB 여부. 실제 DB를 삭제하며 해결하지 않음 |

**LLM 요청·응답**과 진행 상세를 사용합니다. `llm_messages.jsonl`, `answer_diagnostics.jsonl`, `overnight_result.json`은 출력 폴더의 로컬 진단 자료이며 개인정보·원문이 포함될 수 있어 Git에는 올리지 않습니다. API 키 마스킹이 원문까지 익명화한다는 뜻은 아닙니다.

## 검증과 전달

코드가 바뀐 경우 관련 검사 후 영향에 맞게 회귀 검사·배포 검사를 수행합니다. 아래는 기존 명령이며 이번 문서화에서는 모델·Windows 패키지를 다시 실행하지 않습니다.

```sh
.venv/bin/python windows-demo/test_demo.py
.venv/bin/python package_windows.py
```

소스·창작 샘플·예제 설정·보고 문서를 GitHub에 올리고 실제 Excel·DB·설정·모델·로그는 보존 위치에서 관리합니다. 커밋과 푸시는 각각 별도의 Ponytail 검토 및 저장소 루트의 승인 게이트를 거칩니다. 구체적인 절차는 [프로젝트 규칙](../AGENTS.md)을 따릅니다.

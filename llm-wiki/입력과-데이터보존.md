# 입력과 데이터 보존

기준일: 2026-09-29 · 상태: 현재 기능. [목차](index.md) · [문장 정리와 검색](문장정리와-검색.md)

## 두 양식과 원문

| 양식 | 시트 | 업무 번호 | 보관 방법 |
| --- | --- | --- | --- |
| 기존 CS 128열 | `CSList` | `CS 접수번호` | 접수·작업1·작업2의 원문과 근거 ID 유지 |
| 누적 CS 28열 | `19~26년 누적_2600831` | `CS NO` | 원래 28열·언어·자료형·셀 위치 유지 |

두 양식의 같은 업무 번호는 함께 찾지만 원문 문서를 서로 덮어쓰지 않습니다. 자료 목록은 문서 수, 지원하는 전체 접수 집계는 CS 번호 중복을 제외한 건수이므로 숫자가 다를 수 있습니다. 접수 한 건을 검색 문서로 다루되 작업별 근거를 잃지 않는 구조입니다.

열은 지원 양식과 대조하며 알려진 별칭과 UI의 열 대응을 사용합니다. 예를 들어 `Part Decs`와 `Part Desc`, `전산`과 `정산`처럼 실제 양식에서 달랐던 표기는 확인한 대응으로 처리합니다. 모든 오타를 임의 추측하여 연결하지 않습니다. 제목이 빈 중간 열·중복 열·예약 이름·이름 없는 데이터 열은 위치와 함께 오류로 안내합니다. 제목과 데이터가 모두 빈 뒤쪽 열만 제외합니다.

## 읽기와 반복 실험

- 일반 파일은 openpyxl로 읽습니다. 수식을 직접 계산하지 않습니다.
- DRM 파일은 같은 Windows 사용자로 Excel에서 인증하고 연 뒤 **Windows Excel에서 열린 파일**로 읽습니다. 파일을 열거나 저장·종료하는 자동화와 DRM 해제는 수행하지 않습니다.
- Excel 연결은 계산 완료 값을 사용합니다. 계산 중이면 F9 등으로 계산을 마치고 다시 실행합니다. 실제 오류 값·지원하지 않는 병합 등은 계속 검사합니다.
- 셀 편집 중에는 Excel 읽기가 대기할 수 있습니다. Enter로 확정하거나 Esc로 취소하고 대화상자를 처리합니다. 사용자가 보고한 지연 해결 사례이며 모든 지연의 원인이라고 단정하지 않습니다.
- 반복 실험은 **실험용 파일로 변환**하여 `.rag.jsonl.gz`를 재사용합니다. 원문·자료형·셀 위치를 보관하며 원본이 바뀌면 다시 변환해야 합니다. 변환 단계·행 수·건수·경과 시간을 표시합니다.

변환 파일은 원문을 포함하므로 접근 권한과 보관 정책을 적용해야 합니다. Git에는 올리지 않습니다. **입력 검사나 변환만 완료한 것은 DB 등록 완료가 아닙니다.**

출처: [Excel 앱 연결](../ragkit/excel_app.py), [변환 파일](../ragkit/source_cache.py), [README](../README.md).

## 추가·갱신·중복 규칙

| 상황 | 처리 |
| --- | --- |
| 새 접수번호 | 원문을 추가 |
| 같은 양식의 번호와 원문이 같음 | 기존 자료·제안·검토·파생 자료 재사용 |
| 같은 원본 파일의 같은 접수 내용이 변경됨 | 해당 접수 갱신, 기존 검토는 재검토 대상으로 표시, 오래된 파생 자료 제외 |
| 같은 양식의 다른 파일에 같은 번호·다른 내용 | 해당 파일의 등록 실패, 기존 DB 보존 |
| 같은 내용이지만 접수번호가 다름 | 별도 사례 |
| 이번 파일에 기존 접수가 빠짐 | 기존 DB에서 삭제하지 않음 |
| 한 파일 안의 중복 번호 또는 입력 오류 | 그 파일 전체 등록 실패 |

여러 파일 대기열은 최대 100파일을 순서대로 처리합니다. 중복 경로는 제외하고, 실패 파일 이후에도 다음 파일을 처리합니다. 완료 파일은 보존하고 실패 파일만 다시 요청할 수 있습니다. 경로는 서버 PC 기준이며 다른 PC의 브라우저에서 파일을 업로드하는 기능은 아닙니다. 대기열은 서버 재시작 후 자동 복원되지 않습니다.

출처: [누적 등록·검토 저장](../ragkit/storage.py), [웹 대기열](../ragkit/web.py), [누적 등록 검사](../tests/test_incremental.py), [파일 대기열 검사](../tests/test_import_queue.py).

## Excel을 삭제하기 전

DB에 원문 셀·자료형·파일명·시트명·셀 주소를 등록하며 Excel 파일 전체를 바이너리로 보관하지는 않습니다. 등록 건수와 원문을 확인하고, 프로그램을 종료한 뒤 설정과 출력 폴더 전체를 백업합니다. 이 조건을 충족하면 등록 이후 다듬기·검토·번역·벡터·질문에 Excel을 다시 읽지 않습니다.

출처 위치는 등록 당시 기록입니다. 삭제한 Excel을 열 수 있게 해 주거나 DB만으로 원본 서식·매크로를 복원한다는 뜻은 아닙니다. 실제 삭제 작업은 이번 위키 작성에 포함하지 않습니다. [운영과 장애 대응](운영과-장애대응.md)을 함께 확인합니다.

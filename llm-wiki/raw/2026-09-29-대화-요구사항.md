## 자료와 사용 목적

- 여러 사람이 자유롭게 작성한 Excel의 문제 현상으로 과거 해결책을 찾고 싶다. 누락 셀, 표현 차이, 중국어·영어 혼합을 고려해야 한다.
- 원문의 각 셀을 읽기 쉽고 명확한 한국어로 다듬되 숫자·단위·부호·순서와 장비 코드를 보존하고 싶다.
- 처음에는 혼자 사용하는 Python·OpenAI 호환 API 시스템으로 시작하고, Mac LM Studio에서 시험한 뒤 Windows로 전달하고 싶다.
- 모델을 학습하지 않는 구성을 먼저 만들고, 답변 모델과 임베딩 모델의 역할을 이해하고 싶다.
- 초기 양식은 `CSList`, 추가 양식은 `19~26년 누적_2600831`이다. 새 양식의 `CS NO`는 기존 `CS 접수번호`와 같은 업무 번호다.
- DB 등록 후 Excel 원본 파일을 삭제할 계획이므로 등록한 셀과 출처를 DB에서 사용할 수 있어야 한다.
- DRM 파일은 인증된 Excel 앱을 통해 xlwings로 읽고 싶다. 반복 실험에서는 한 번 변환한 별도 파일을 재사용하고 싶다.
- 새 Excel 자료를 누적 등록하고 여러 파일을 대기열에 넣고 싶다. 중복 내용과 같은 번호의 다른 내용이 어떻게 처리되는지 확인하고 싶다.

## 자동화와 검토

- 문장 다듬기 JSON을 다운로드해 수동으로 다시 넣는 단계를 없애고 DB에 자동 저장하고 싶다.
- 실패가 있어도 다른 자료의 처리를 계속하고, 성공분을 재사용하며 오류 이유를 넣어 재요청하고 싶다.
- 숫자·측정 단위의 짝과 순서가 변했다는 오류, 수정 대상 열 누락·추가 오류를 개선하고 싶다.
- 여러 셀과 많은 접수의 제안을 일괄 검토·반영하고 싶다.
- 문장 다듬기와 영어 번역을 병렬 처리하고, UI에서 동시 처리 수를 설정하고 싶다. 후속 요청은 기본 200, 최대 1,000이다.
- 영어 번역은 실패 사유를 반영해 세 번 보완 요청하고 싶다.
- 퇴근할 때 실행해 아침에 검색할 수 있도록 준비하고 싶다. 검사 통과 제안의 자동 채택을 승인했고, 야간에는 실패가 남으면 반복 요청하기를 원했다.
- 진행 단계·경과 시간·오류 위치와 LLM 요청·응답을 확인하고 싶다.

## 검색과 답변

- 접수 한 건을 한 문서로 다루고, 현상 중심으로 과거 원인·조치·결과를 찾고 싶다.
- 한국어 검색에서 두 글자 조각의 역할과 2그램·3그램 차이를 검토했다.
- 영어 번역문과 영어로 번역한 질문을 검색에 함께 사용하는 방향을 요청했다.
- 벡터 검색을 추가하고, 임베딩 준비 이후 매번 별도로 모델·색인을 실행하는 수고를 줄이고 싶다.
- PostgreSQL·pgvector, 영어 번역문 자체의 벡터화, 경량 판단 모델·학습 가능성을 검토했다. 검토 질문만으로 도입했다고 간주하지 않는다.
- 답변과 원문 전체가 중복되어 지저분해지는 문제를 줄이고 인용 근거를 별도로 읽고 싶다.
- 참고 사례 수를 UI에서 바꾸고 모델 문맥 길이에 맞춰 자동 선택하고 싶다.
- 과거 조치의 날짜를 포함하되 인용 중복은 줄이고 싶다. 숫자·부호의 인용 근거 오류와 긴 보정 요청 오류를 보고했다.
- 답변에 이어서 질문하고, AI 지시 언어를 영어로 선택할 수 있기를 원했다.
- 여러 PC가 웹 UI에 접속하고 동시에 질문할 때의 동작을 확인·개선하고 싶다.

## 실험·전달·설계 지식

- 현실적인 누락·다국어·수치 사례를 만들고, 가상 2,000건에서 100,000건으로 시험 자료를 늘리고 싶다. 가상 자료 성능을 실제 업무 성능으로 간주하지 않는다.
- Mac과 Windows의 모델이 달라도 효과를 비교하고, 추론 옵션·토큰 한도를 서버에 맞게 사용하고 싶다.
- GLiNER2.5-Decide, LEV, CLM, Laya-CoreML, Ollaya를 비교해 적합률과 처리 시간을 확인하고 싶다. 기존 GPU 실험을 끝낸 후 다음 큰 모델 실험을 실행하도록 순서를 지정했다.
- 불필요한 코드·파일·DB 구조를 줄이되 데이터 보존과 성능을 유지하고 싶다.
- Apple 스타일 UI, 쉬운 주석, 실행 매뉴얼, 한국 시간으로 이름을 붙인 Windows 전달 파일을 원했다.
- GitHub에 코드와 설명을 함께 올리고, 흐름도와 비개발자도 이해할 임원 보고서를 유지하기를 원했다.
- Karpathy의 LLM Wiki를 참고한 뒤, **지금까지의 내용을 llm-wiki에 작성**하도록 요청했다. 직전에 제안한 설비·증상별 종합 요약의 RAG 품질 비교는 아직 수행 결과가 없다.

## 사용자 보고와 검증을 구별할 항목

- DRM 읽기 지연은 셀 편집 중 대기 때문에 발생했고 편집을 끝내 해결했다고 사용자가 보고했다. 모든 DRM 제품의 호환성을 검증했다는 뜻은 아니다.
- 일부 숫자·인용 오류는 이 Mac의 DB가 아닌 다른 DB에서 발생했다. 해당 실제 원문·응답이 없으면 동일 사건을 재현했다고 쓰지 않는다.
- Windows 실제 모델은 GPT OSS 120B라고 사용자가 설명했다. API 별칭이 `gpt-4`로 남아 있는 것만으로 실제 기반 모델을 판별하지 않는다.

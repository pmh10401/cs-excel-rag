1. 자료 등록 Excel · 변환 파일 · 여러 파일 대기열

CSList(128열)와 19~26년 누적_260925(28열, SITE·불량발생년월)를 지원하며 구형 누적 시트도 읽습니다. 같은 CS NO의 다른 부품·내용은 각각 보관하고 완전히 같은 행은 첫 위치로 한 번 처리합니다. 중국어·영어 설명은 문장 다듬기에서 한국어로 번역합니다.

읽기 방식

DRM 파일은 Excel에서 인증 후 열어 두세요. 셀을 편집 중이면 Enter로 확정하거나 Esc로 취소하고, 열린 대화상자를 처리한 뒤 실행하세요.

등록 방식과 원문 보존 안내

DB 등록 후에는 Excel 없이 처리합니다. 누적 28열은 같은 CS NO라도 값·자료형이 다르면 별도 상세로 추가하며, 문장을 수정한 행도 기존 상세를 덮어쓰지 않습니다. 같은 내용은 재사용하고 파일에서 빠진 기존 자료는 보존합니다. CSList는 기존처럼 같은 파일의 수정 건을 갱신하고, 다른 파일의 동일 번호·다른 내용은 충돌로 알립니다. 자료 목록은 상세 문서 수, CS 집계는 중복 번호를 제외한 건수입니다.

다듬기는 DB 전체를 대상으로 하며 성공한 제안은 중간 저장합니다. 실험용 파일 변환은 모델 없이 원문·자료형·셀 주소를 보존합니다. 원본 Excel이나 열 대응을 바꿨다면 다시 변환하세요.

Excel 응답 대기가 길면 셀 편집 상태와 열린 대화상자를 확인하세요. Enter는 편집 확정, Esc는 편집 취소입니다.

여러 파일 등록 대기열

프로그램이 실행되는 PC의 경로를 사용합니다. 위에서 선택한 읽기 방식으로 순서대로 등록하며, 변환 파일은 일반 파일로 읽습니다. DRM 파일은 모두 Excel에서 열고 셀 편집을 끝내세요. 실패한 파일이 있어도 다음 파일을 계속 처리합니다.

같은 경로는 한 번만 처리하고, 번호·원문이 같은 자료는 재사용합니다. 내용 충돌은 해당 파일 전체를 제외합니다. 브라우저를 닫아도 처리는 계속되지만 프로그램 재시작 시 대기 목록은 초기화됩니다. 등록 후 DB 문장 다듬기 또는 야간 자동 실행을 누르세요.

    열 이름 대응

    내보내기마다 다른 열 이름을 이 양식 열에 맞춥니다. 저장한 뒤에 입력 검사를 다시 통과해야 문장 다듬기를 실행할 수 있습니다. 자동으로 맞추거나 열을 빼지 않습니다.

      개별 실행 벡터 · 영어 번역

      벡터 검색 자료

      표현이 달라도 의미가 비슷한 현상을 찾습니다. 별도 임베딩 모델이 필요하며, 현재 설정 파일에서 지정합니다.

      임베딩 설정이 있으면 시작 시 서버·모델을 준비하고, DB 등록·변환·검토 저장 후 필요한 벡터를 자동 생성합니다. 아래 버튼은 일부만 시험하거나 실패분을 다시 처리할 때 사용합니다.

      등록된 DB를 사용하며 Excel이 필요하지 않습니다. 기존 수정 제안·검토는 유지합니다. 임베딩은 현상·제목·설비 정보와 채택문을 사용하며, 동일 내용은 재사용합니다. 일부만 생성하면 벡터 검색도 그 범위로 제한됩니다.

      영어 검색 자료

      한국어 원문과 검토 결과를 유지하며 현상·원인·조치·제목의 영어 번역을 추가합니다. 먼저 일부 자료로 검색을 비교한 뒤 전체를 처리하세요.

      성공 건은 자동 저장하고 실패 건을 건너뛰어 계속 진행합니다. 설정에서 자동 갱신을 켜면 검토 저장 후 영어 자료를 갱신합니다. 꺼져 있으면 직접 변환하세요. 실패 건 재시도는 처리 범위 선택과 관계없이 실패한 자료 전체를 처리합니다. 번역은 검색 보조 자료이며 답변 근거는 한국어 원문입니다.

      문장 검토

      접수를 고른 뒤 원문과 수정문을 비교합니다. 여러 셀을 선택해 일괄 채택하거나 원문을 유지할 수 있습니다. 검토 저장을 누르면 변경한 셀 모두가 DB에 반영됩니다.

      현재 자료 전체 처리

      검색 조건·페이지와 관계없이 미검토 수정 제안을 모두 채택하고 저장합니다. 기존 채택·원문 유지·직접 편집은 보존합니다. 빈 셀·제안 없는 접수·검사에 실패한 제안은 제외합니다.

      화면에서 변경한 검토가 있다면 먼저 검토 저장을 누르세요.

        저장하지 않은 검토 변경이 있습니다.

        왼쪽 목록에서 접수를 선택하세요.

        질문

        문제 현상을 입력하면 유사한 과거 사례의 조치와 관찰 결과·미확인 사항을 찾아봅니다. 설비명·알람 코드·발생 조건을 함께 쓰면 범위를 좁힐 수 있습니다.

        질문은 접수 순서대로 처리합니다. 내 브라우저에서는 한 번에 한 건을 제출하며 새로고침해도 상태를 확인할 수 있습니다. 서버를 종료하면 대기·결과는 초기화됩니다.

        새 질문입니다.

        최근 대화 확인

        최근 5문답을 이 브라우저 세션에 보관합니다. 후속 질문은 최근 최대 3문답으로 대상을 파악하고 DB 원문을 다시 검색합니다. 서버 재시작·세션 만료 시 초기화됩니다.

        접수번호·코드·날짜는 정확 검색을 사용합니다. 결합 검색은 벡터를 사용할 수 없으면 키워드 검색으로 진행하고 이유를 표시합니다.

        관계 보완은 같은 상세·작업에 적힌 설비·모듈·부품 이름이 두 종류 이상일 때 사용합니다. 등록된 숫자 포함 코드도 지원하며, 측정값·날짜·수량·부정·정상 조건은 기존 검색을 유지합니다. 연결만으로 원인·조치 성공을 판단하지 않습니다.

        질문하거나 검색을 비교하면 설정이 저장됩니다. 자동은 상위 100건 안에서 질문·원문·답변 및 추론 분량을 고려합니다. 서버 문맥을 확인하지 못하면 설정값 또는 문자 제한을 사용하며 결과에 표시합니다. 원문 셀은 자르지 않습니다.

        답변·보정·후속 질문 정리 지시의 언어를 선택합니다. 원문과 인용 검사는 유지하며 영어 질문 번역 설정과는 별개입니다. 영어 지시가 더 정확하다는 뜻은 아닙니다.

        한국어 질문을 한 번 번역해 원문과 함께 답변 모델에 전달합니다. 영어 검색 자료가 있으면 키워드·결합 검색에도 활용합니다. 벡터 질의는 원문을 사용하며, 번역 실패 시 원문만으로 계속합니다.

        검색만 비교는 검색 후보와 관계 경로를 보여 줍니다. 답변 모델은 호출하지 않으며, 코드 정확 검색은 임베딩 호출도 생략합니다.

        답변

        문맥을 반영한 검색 질문

        이전 답변은 질문 이해에만 사용합니다. 사실과 인용은 이번에 검색한 DB 원문으로 검사합니다.

        영어 번역 질문 확인

        질문 이해를 위한 보조 표현입니다. 답변과 인용 근거는 한국어 원문을 기준으로 합니다.

        관계 보기 · 검색된 상세와 원문

        연결선은 같은 상세·작업의 원문에 함께 기록된 이름을 뜻합니다. 원인이나 조치 성공을 증명하지 않습니다.

            사례를 선택하면 해당 상세의 발생일·현상·원인·조치 원문을 확인할 수 있습니다.
